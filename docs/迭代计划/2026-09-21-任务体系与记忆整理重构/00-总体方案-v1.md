# 知我时光笺 · 任务/计划/目标体系重构 + 记忆整理残存修复 —— 总体方案 v1

日期：2026-09-21　执行：AI（Qoder）　评审门禁：AI 子代理评分 ≥90 才可开工

---

## 0. 一句话说明要干什么

把现在「任务只是记录的附属品」的结构，改成「目标 → 计划 → 任务」三层真正的对象，任务分成**每日固定 / 临时一次性 / 每日留白**三种，每天自动刷新、可设起止日期、可按工作日或节假日决定做不做、可指定哪天出现、没做完标过期并能填未完成原因；同时把记录页「安排」Tab 重排成能一眼看懂的分段视图，并支持手动新建/编辑（现在**根本没有手动建任务的入口**）。另外修掉记忆页「一键整理后总有残存记忆」的实际缺陷。

## 2. 设计总则（5 条，所有小计划共同遵守）

1. **一条规则只有一个实现处**：任务"今天该不该显示/算不算完成"收敛到唯一入口 `TaskScheduleEngine`，UI、日历、日记、评价、导出、AI 摘要全部调用它。编译器负责兜住漏改（删掉旧列，引用即报错）。
2. **定义与执行分离**：任务是"定义"（重复规则、起止日），打卡是"执行记录"（occurrence，一天一条）。不再往任务行上写完成态。
3. **occurrence 按需落库**：只有用户真的打卡/填原因才写行，每天打开页面不批量插表。"今天有什么"由纯函数算出来。
4. **迁移可回溯**：v12→v13 首次启动时把 tasks 全表原样备份成 JSON 落在应用私有目录，设置页显示备份是否存在；迁移失败仍走已有 `AppDatabase.rebuild()` 三件套备份（AppDatabase.kt:146-171）。
5. **不可验证的事不谎称验证**：Room 迁移与 UI 交互本机无模拟器，一律进「用户实测清单」并标注"需你确认"，不算通过。

## 3. 数据模型（v13）

### 3.1 新表 `goals`（目标：长期，一年/几年尺度）
`id` `title` `description` `startDate`(可空) `targetDate`(可空=无截止) `status`(active/achieved/abandoned) `recordId`(可空，溯源记录，不设 FK 以免删记录牵连目标) `sortOrder` `createdAt` `updatedAt`

### 3.2 新表 `plans`（计划：一段时间，一个月/一季尺度）
`id` `goalId`(FK→goals，SET NULL) `title` `description` `startDate` `endDate`(可空) `status`(active/done/dropped) `recordId` `sortOrder` `createdAt` `updatedAt`

### 3.3 重建表 `tasks`（任务：具体要做的一件事）
保留：`id` `content`(标题文本，列名不改，减少 60+ 处引用改动) `recordId`(FK CASCADE，维持现语义) `calendarEventId`
新增：
- `kind`：`daily`（每日要完成的）| `adhoc`（临时一次性）| `blank`（每日留白）
- `repeatRule`：`everyday` | `weekdays`（周一至周五）| `custom`（配合 `weekdaysCsv`）| `interval`（配合 `intervalDays`）——仅 daily
- `weekdaysCsv`（`1,3,5`，ISO 周一=1）、`intervalDays`
- `dayPolicy`：`all` | `workday_only` | `holiday_only` —— 节假日/调休补班由 `FestivalProvider` 判定
- `startDate`（空=立即生效）、`endDate`（空=长期）→ 长期/短期任务都支持
- `scheduledDate`（adhoc 专用：指定哪天才开始显示）、`dueDate`（最后期限，空=无期限）
- `durationMinutes`（0=不限）、`remindTime`（`HH:mm`，空=不提醒）
- `goalId` `planId`（可空 FK）——任务的归属，替代 `parentGoalId`
- `status`：`active` | `paused`（暂停，不刷新不上账）| `archived`（结束/放弃，保留历史）
- `colorIndex`（0-5 自定义颜色）、`sortOrder`

删除（重建表时一并去掉）：`taskType` `isCompleted` `completedAt` `dailyCompletionDate` `isPermanentlyCompleted` `parentGoalId`

### 3.4 新表 `task_occurrences`（打卡记录）
`id` `taskId`(FK CASCADE) `date`(yyyy-MM-dd) `status`(`done` | `not_done`) `reasonCode`(`''`/`no_time`/`tired`/`sick`/`forgot`/`changed`/`other`) `reasonNote`(自由文本) `actualMinutes` `note`（**留白任务回填这小时干了什么**）`updatedAt`
唯一索引 `(taskId, date)` + `OnConflictStrategy.REPLACE` → 天然幂等，重复点击不会攒脏数据。

### 3.5 存量映射（迁移函数是纯函数，JVM 可测）
| 旧 | 新 |
|---|---|
| `taskType='daily'` | `kind='daily'`, `repeatRule='everyday'`, `dayPolicy='all'` |
| `taskType='weekly'` | `kind='daily'`, `repeatRule='custom'`, `weekdaysCsv=ISO(dueDate 的星期)` |
| `taskType='once'` | `kind='adhoc'`, `scheduledDate=date(dueDate)`, `dueDate=''` |
| `taskType='goal'` | `kind='adhoc'`（里程碑性质），并按 3.6 挂 goalId |
| `isCompleted=1` 且 `dailyCompletionDate` 非空 | 写 occurrence(`date=dailyCompletionDate`, `status='done'`) |
| `isCompleted=1` 且（adhoc 或 `isPermanentlyCompleted=1`） | occurrence(`date=completedAt 日期` 或今天, `done`) |
| `isPermanentlyCompleted=1` | 再置 `status='archived'`（保持"不再每日刷新"的老语义） |
| `parentGoalId` 指向 category=goal 的记录 | 为每个不同 id 建一行 goal（title/description/recordId 取自该记录），任务挂 `goalId` |

迁移不可逆的部分只有「删列」，因此 JSON 原表备份是硬要求（设计总则 4）。

## 4. 排期引擎（`data/tasks/TaskScheduleEngine.kt`，纯 Kotlin，无 Android 依赖）

```kotlin
enum class TaskState { DUE_TODAY, DONE_TODAP, NOT_DONE_TODAY, OVERDUE, UPCOMING, PAUSED, ENDED, BLANK_UNFILLED }
data class DayEntry(val task: TaskEntity, val occurrence: TaskOccurrence?, val state: TaskState, val section: Section)
enum class Section { DAILY_FIXED, DAILY_BLANK, TODAY_ADHOC, OVERDUE, DONE_TODAY }

fun dayTypeOf(date: String, specialDates: List<SpecialDateEntity>): DayType  // WORKDAY / HOLIDAY
fun entriesFor(date: String, tasks: List<TaskEntity>, occurrences: List<TaskOccurrence>, dayType: DayType): List<DayEntry>
fun isEffectivelyDone(task, occurrence, date): Boolean     // 取代现有 4 份实现
fun progressOf(planOrGoalId, range, occurrences): Progress // 计划/目标进度、连续天数
```
判定顺序（每条任务只走一次，短路）：
1. `status != active` → 不出现（paused/archived 只在"已暂停/已结束"二级列表可见）
2. `date` 不在 `[startDate, endDate]` → 不出现（未来日 → UPCOMING）
3. kind=daily：重复规则不匹配 → 不出现；`dayPolicy=workday_only` 且当天是节假日 → 不出现（反之同理）
4. kind=adhoc：`scheduledDate` 非空且 != date → 不出现（> date 为 UPCOMING，< date 未打卡 → OVERDUE）；`scheduledDate` 空则创建当天起持续出现，直到打卡或超过 `dueDate` → OVERDUE
5. kind=blank：每天出现一次（受 dayPolicy 约束），状态 DUE_TODAY / BLANK_UNFILLED（跨天未回填，不算"失败"，进"待回填"）
6. 有 occurrence 且 `status=done` → DONE_TODAY 段；`status=not_done` → NOT_DONE_TODAY（今天显示，带原因，可改）

## 8. 记忆整理残存修复（范围与 E 小计划一致，列此保证整体闭环）

七条根因逐条修：①旧批次遗留提案在整理页顶部常驻显示「有 N 条未处理」并可继续/丢弃；②默认视图排除 `superseded`/`under_review`，"已更正"移到二级页且提供物理删除；③去重从整句全等改为归一化+包含式近义判定（复用 `ReviewViewModel.filterNewMemories:383-403` 的归一化思路）；④`dismiss` 级联取消下游依赖；⑤每条 DELETE 提案只删自己的 `sourceIds`（现在是"单条即删全集"，OrganizeViewModel.kt:585-615）；⑥记忆的合并/拆分统一到 organize_ops 两阶段链路（新增 `MERGE_MEMORY`/`SPLIT_MEMORY` op），删掉 MemoryViewModel 里那套硬删、无事务、无幂等校验的并行实现（:246-392）；⑦`getMemoryCount`/`deleteOldestMemories` 统计口径与列表一致（现在把 superseded 计入上限、按 createdAt 淘汰会把新整理项挤掉）。

## 11. 交叉回归清单（做完 B 回头查 A，做完 C/D/E 回头查前面全部）

1. 建一条 daily 固定任务 → 今天出现；改 endDate 到昨天 → 今天不出现；改 dayPolicy=workday_only 且今天是节假日 → 不出现。
2. 同一任务今天打卡 → 移到"今日已完成"；明天重新出现（**不得再依赖启动时改表**）。
3. adhoc 任务 scheduledDate=2026-09-22 → 9-21 不显示，9-22 显示，9-23 未完成进"已过期"。
4. blank 任务 → 今天出现；不回填到明天不显示为失败；回填内容在"今日已完成"与详情页可见，且进 AI 评价摘要。
5. 打卡"没做完 + 原因" → 该 occurrence 保留原因，安排页显示"未完成·原因"，改判完成后原因保留可编辑。
6. 目标→计划→任务三级：删掉计划不影响目标；目标标记完成 → 其下任务与闹钟按现逻辑收尾 + 触发记忆对账（原能力不得丢失）。
7. 日历页某天 = 安排页同天的集合（同函数、同结果）。
8. 闹钟：新建/编辑/删除任务后 `adb dumpsys alarm`（或设置页"当前提醒列表"）与之一一对应；重启手机后重复任务提醒仍在（需真机，进实测清单）。
9. 导出 JSON version=3 可被导入路径读取；旧 version=2 导出文件仍可导入（导入侧向后兼容读）。
10. AI 抽取记录里的任务：新字段非法/缺失时不崩、回退到 adhoc。
11. 记忆页：一键整理应用后，被合并/取代的记忆**不再出现在默认列表**，且"已更正"二级页可彻底删除；重复整理不产生第 3 条同义记忆。
12. 整理页遗留提案批次：升级后旧 PENDING 提案仍可见、可处理，不会永久 BLOCKED。

## 12. 明确不做（范围控制）

- 不改底部导航结构、不引入 DI 框架（保持现有手动构造 Repository 风格）。
- 不做多人同步/云端、不做商业化相关（私人自用）。
- 不做农历重复规则（`SpecialDateEntity` 已有 isLunar，但任务重复规则本轮只做公历 + 节假日策略）。
- 不重写日记/评价功能本身，只把它们的任务口径接到引擎上。
- 不做"任务模板/预设库"，等三层模型跑稳后再谈。
