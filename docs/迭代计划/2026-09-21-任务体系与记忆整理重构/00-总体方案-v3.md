## 3. 排期引擎（v3 契约，替换 v2 §3）

```kotlin
enum class DayType { WORKDAY, HOLIDAY }
enum class EntrySection { DAILY_FIXED, DAILY_BLANK, ADHOC_TODAY, MISC_TODO, OVERDUE, MISSED, UNFILLED }
enum class EntryState { DUE, DONE, NOT_DONE, OVERDUE, UNFILLED }

sealed interface DayEntry {
    val state: EntryState
    val sourceLabel: String?          // 来自哪个计划/目标，行内 "#法考冲刺"
    data class FromTask(val task: TaskEntity, val occurrence: TaskOccurrenceEntity?) : DayEntry
    data class FromMiscRecord(val record: RecordEntity) : DayEntry   // category=todo 且无任务的记录
}
data class DayPlanResult(
    val planned: List<DayEntry>,      // 四个应做段（DAILY_FIXED/DAILY_BLANK/ADHOC_TODAY/MISC_TODO），含已完成
    val done: List<DayEntry>,         // = planned.filter { it.state == DONE }，仅呈现分组，不占 Section
    val extra: Map<EntrySection, List<DayEntry>>,   // OVERDUE / MISSED / UNFILLED
    val dueCount: Int,                // == planned.size，当天固定，不随打卡变化
    val doneCount: Int,               // == done.size，单调不减
    val issues: List<String>
)
data class Progress(val due: Int, val done: Int, val percent: Int, val streak: Int,
                    val missed: Int, val from: String, val to: String)
sealed interface OwnerId { data class Goal(val id: Long) : OwnerId; data class Plan(val id: Long) : OwnerId }
data class MissedItem(val task: TaskEntity, val date: String)
data class UnfilledItem(val task: TaskEntity, val date: String)

fun dayTypeOf(date: String, holidays: Set<String>, makeupWorkdays: Set<String>, overrideType: String?): DayType
fun isScheduledOn(task: TaskEntity, date: String, dayType: DayType, parentStatusById: Map<Long, String> = emptyMap()): Boolean
fun entriesFor(date: String, tasks: List<TaskEntity>, occurrences: List<TaskOccurrenceEntity>,
               dayType: DayType, parentStatusById: Map<Long, String> = emptyMap(),
               sourceNames: Map<Long, String> = emptyMap(),
               miscTodoRecords: List<RecordEntity> = emptyList()): DayPlanResult
fun upcomingAdhoc(tasks: List<TaskEntity>, date: String): List<TaskEntity>
fun missedOn(tasks, occurrences, from, to, dayTypeOf: (String) -> DayType, lookbackDays: Int = 30): List<MissedItem>
fun unfilledBlanks(tasks, occurrences, today, windowDays: Int = 7): List<UnfilledItem>
fun isEffectivelyDone(task, occurrence, date): Boolean
fun streakOf(taskId, occurrences, today, dayTypeOf): Int
fun progressOf(tasks, plans, goals, occurrences, overrides, from, to): Map<OwnerId, Progress>
```
保证（逐条有命名用例）：
- **G1** 每个 task 至多一条 `FromTask`；每条 misc 记录至多一条 `FromMiscRecord`；结果无 null 元素。
- **G6′** `dueCount = planned.size` 与 `EntryState` 无关 → 完成率 `doneCount/dueCount` 的**分母当天恒定**（修 MF-5）。段头 `3/5` 用「该段 planned 中 DONE 数 / 该段 planned 数」。
- 其余 G2-G7 同 v2（幂等无副作用、排序 `section→sortOrder→id`、`status!=active` 不产出、未到期 adhoc 走 `upcomingAdhoc`、解析失败进 `issues`、双归属不双算）。
- 新增 `MF-G06_打卡进度不改变dueCount` 用例：同一批数据在"全未完成 / 部分完成 / 全完成"三种 occurrence 输入下，`dueCount` 必须相等（这条直接钉死 MF-5 的复发）。

## 9. 数据安全与失败处理（v3 整段重写，替换 v2 §9）

**原则：任何路径都不得让老板打开 App 看到空数据库。**

1. **两条失败路径分离**：
   - `P1 库文件损坏/打不开`（迁移前就打不开）→ 允许备份 + `rebuild()`，备份目标改到 `getExternalFilesDir("migration_backup")`（现在的 `AppDatabase.kt:146-171` 备份到 `databases/` 目录内部，release 无 root **取不出来**）。
   - `P2 迁移异常 / 自检不通过`（本项目最可能的那种）→ **禁止 rebuild**。动作：关闭 helper → settings 写 `MIGRATION_FAILED=<阶段,原因,备份路径>` → 以**恢复模式**启动（`MainActivity` 见标记只渲染"恢复模式"界面：显示备份位置 + 「还原到升级前」+「重试迁移」两个按钮 + 退出 App），完成后 `exitProcess(0)`。**绝不允许在 P2 下让 DAO 被使用**。
2. **备份自洽**：复制三件套前先 `PRAGMA wal_checkpoint(TRUNCATE)`（沿用 `AppDatabase.kt:155` 的既有做法），复制后再 checkpoint 一次防复制后又增长；目录 `migration_backup/pre_v13_<ts>/`、`pre_v14_<ts>/`。
3. **备份可证**：迁移内写 tasks 全表 JSON → **回读** → 行数必须 == 老表 `COUNT(*)`；写不进去或回读不符 → 判 P2。
4. **迁移后自检**：`tasks` 行数不变、`task_occurrences` 条数 == 映射函数预期、v14 另加"重建前后 occurrence 计数相等"，任一不符 → 判 P2（不判 P1）。
5. **`ensureDatabaseReady()` 同步化**：`ZhiwoApplication.onCreate` 里同步完成"打开/迁移/自检/失败分级"，替换现在 :55-70 的异步预热 + catch-all rebuild（现在这个写法正是 MF-1 的成因）。
6. **回滚入口**：设置页 + 恢复模式页都提供「恢复到升级前」（关库 → 还原三件套 → `exitProcess`）。覆盖范围只有"迁移前一刻"，文案照实写，不宣称通用回滚。
7. **调试可见性**：设置页显示 当前 DB 版本 / 上次迁移结果 / `migration_v13_report` 条数 / 备份目录是否存在与大小 / 节假日数据来源与录入日期。真机验收第一步就是读这几个数，别拿猜测当基线。
8. grep 门禁：`rebuild(` 在 `app/src/main` 只允许被 P1 分支调用（其余命中即失败）。
