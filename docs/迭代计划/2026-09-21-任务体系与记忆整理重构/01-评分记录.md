记忆上限只约束 active + superseded 定期物理清理（采纳，E.1）；`EntryState`/`EntrySection` 与页面 7-8 段一一对应并去掉 `DONE_TODAP` 拼写（采纳）；日历网格区分"例行打卡"与"专属事件"两种标记（采纳，否则整月全亮）；历史日记/评价改用 occurrence 后，v13 之前的历史日期会显示未完成 —— 属可见行为变化，写进实测清单而非当 bug（采纳）；AI 抽取非法值不再一律回退 adhoc，改按 `dueDate` 是否含时间/关键词回退 `daily/everyday`（采纳）；定义 `remindTime` 与 `REMIND_MINUTES_BEFORE=15`、`EVENT_DURATION_MILLIS`、`durationMinutes` 四者关系（采纳）；备份提示复用现有 SettingsScreen 备份 UI 区（采纳）；新 op 必须同时进 `OpType.executionOrder()` 与 `OpValidator.decide`（采纳，E.4 加门禁）；C 拆为 C1（引擎接线+只读展示）/C2（编辑器+打卡交互）（采纳）；列出基线用例改写清单（采纳）。

### 评审 A 提出的 6 个疑问 → 本轮定的默认（老板可否决）
1. 节假日数据：内置 2026 年公告数据（实现时联网核对原文）+ 用户手动标"班/休" + 周末兜底；2027 公告未出则该年按周末判定并在设置页注明。
2. 「指定哪天出现」= 那天出现在今日列表；那天没做完 → 之后进"已过期"。（贴用户原话"只有在那一天才开始显示，没做完就会显示过期"）
3. 留白默认归属当天；跨零点可手动改归属日。
4. 老的目标记录仍留在记录流（历史不删），安排/目标页一律读新 goals 表。
5. 记录型待办：保留过渡段 + "转为任务"，不批量改写用户数据。
6. 交付包：日常用 debug APK；真机迁移验收另出 release 包（构建失败会如实报告，不静默降级）。
