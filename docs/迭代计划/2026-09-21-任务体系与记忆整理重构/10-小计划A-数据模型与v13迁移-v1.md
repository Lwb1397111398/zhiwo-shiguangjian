## A.2 表结构（DDL 原文，与实体逐列对齐）

```sql
-- goals
CREATE TABLE IF NOT EXISTS `goals` (
  `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  `title` TEXT NOT NULL,
  `description` TEXT NOT NULL DEFAULT '',
  `startDate` TEXT NOT NULL DEFAULT '',      -- yyyy-MM-dd，'' = 未设
  `targetDate` TEXT NOT NULL DEFAULT '',     -- 截止日，'' = 长期
  `status` TEXT NOT NULL DEFAULT 'active',   -- active | achieved | abandoned
  `recordId` INTEGER,                        -- 溯源记录，不设 FK（删记录不牵连目标）
  `sortOrder` INTEGER NOT NULL DEFAULT 0,
  `createdAt` TEXT NOT NULL,
  `updatedAt` TEXT NOT NULL DEFAULT ''
)

-- plans
CREATE TABLE IF NOT EXISTS `plans` (
  `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  `goalId` INTEGER,
  `title` TEXT NOT NULL,
  `description` TEXT NOT NULL DEFAULT '',
  `startDate` TEXT NOT NULL DEFAULT '',
  `endDate` TEXT NOT NULL DEFAULT '',        -- '' = 未设截止
  `status` TEXT NOT NULL DEFAULT 'active',   -- active | done | dropped
  `recordId` INTEGER,
  `sortOrder` INTEGER NOT NULL DEFAULT 0,
  `createdAt` TEXT NOT NULL,
  `updatedAt` TEXT NOT NULL DEFAULT '',
  FOREIGN KEY(`goalId`) REFERENCES `goals`(`id`) ON UPDATE NO ACTION ON DELETE SET NULL
)
CREATE INDEX IF NOT EXISTS `index_plans_goalId` ON `plans` (`goalId`)

-- tasks（重建；`content` 列名沿用，避免 60+ 处引用改名）
CREATE TABLE `tasks_new` (
  `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  `content` TEXT NOT NULL,
  `recordId` INTEGER,
  `goalId` INTEGER,
  `planId` INTEGER,
  `kind` TEXT NOT NULL DEFAULT 'adhoc',          -- daily | adhoc | blank
  `repeatRule` TEXT NOT NULL DEFAULT 'everyday', -- everyday | weekdays | custom | interval
  `weekdaysCsv` TEXT NOT NULL DEFAULT '',        -- "1,3,5" ISO 周一=1，仅 custom
  `intervalDays` INTEGER NOT NULL DEFAULT 1,     -- 仅 interval
  `dayPolicy` TEXT NOT NULL DEFAULT 'all',       -- all | workday_only | holiday_only
  `startDate` TEXT NOT NULL DEFAULT '',          -- daily 生效区间起，'' = 立即
  `endDate` TEXT NOT NULL DEFAULT '',            -- daily 生效区间止，'' = 长期
  `scheduledDate` TEXT NOT NULL DEFAULT '',      -- adhoc：哪天开始显示，'' = 创建当天起
  `dueDate` TEXT NOT NULL DEFAULT '',            -- adhoc：最后期限，'' = 无期限
  `durationMinutes` INTEGER NOT NULL DEFAULT 0,  -- 0 = 不限；blank 默认 60
  `remindTime` TEXT NOT NULL DEFAULT '',         -- "HH:mm"，'' = 不提醒
  `status` TEXT NOT NULL DEFAULT 'active',       -- active | paused | archived
  `colorIndex` INTEGER NOT NULL DEFAULT 0,
  `sortOrder` INTEGER NOT NULL DEFAULT 0,
  `calendarEventId` INTEGER,
  `createdAt` TEXT NOT NULL,
  FOREIGN KEY(`recordId`) REFERENCES `records`(`id`) ON UPDATE NO ACTION ON DELETE CASCADE,
  FOREIGN KEY(`goalId`)   REFERENCES `goals`(`id`)   ON UPDATE NO ACTION ON DELETE SET NULL,
  FOREIGN KEY(`planId`)   REFERENCES `plans`(`id`)   ON UPDATE NO ACTION ON DELETE SET NULL
)
CREATE INDEX `index_tasks_recordId` ON `tasks_new` (`recordId`)
CREATE INDEX `index_tasks_goalId`   ON `tasks_new` (`goalId`)
CREATE INDEX `index_tasks_planId`   ON `tasks_new` (`planId`)

-- task_occurrences（打卡记录，按需落库）
CREATE TABLE IF NOT EXISTS `task_occurrences` (
  `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  `taskId` INTEGER NOT NULL,
  `date` TEXT NOT NULL,                        -- yyyy-MM-dd
  `status` TEXT NOT NULL DEFAULT 'done',       -- done | not_done
  `reasonCode` TEXT NOT NULL DEFAULT '',       -- '' | no_time | tired | sick | forgot | changed | other
  `reasonNote` TEXT NOT NULL DEFAULT '',
  `actualMinutes` INTEGER NOT NULL DEFAULT 0,
  `note` TEXT NOT NULL DEFAULT '',             -- 留白任务回填"这小时干了什么"
  `createdAt` TEXT NOT NULL,
  `updatedAt` TEXT NOT NULL DEFAULT '',
  FOREIGN KEY(`taskId`) REFERENCES `tasks`(`id`) ON UPDATE NO ACTION ON DELETE CASCADE
)
CREATE UNIQUE INDEX IF NOT EXISTS `index_task_occurrences_taskId_date`
  ON `task_occurrences` (`taskId`, `date`)
```

### A.2.1 列语义约束（写进实体注释与测试）
- 所有日期列一律 `yyyy-MM-dd` 文本，空串=未设置。**禁止**再往日期列写 `yyyy-MM-dd HH:mm:ss`（旧 `dueDate` 就是混着存才导致 `SUBSTR(x,1,10)` 满天飞）。
- `scheduledDate` 与 `dueDate`：允许 `dueDate < scheduledDate`（脏数据），引擎按"到期即过期"处理，不静默丢任务。
- occurrence 唯一索引 `(taskId,date)` + `@Insert(onConflict = REPLACE)` → 同一任务同一天只有一条，重复提交是覆盖不是新增（幂等，这是修"残存脏数据"的同一条路）。

## A.3 迁移步骤（`MIGRATION_12_13`，顺序即正确性）

```
0) 迁移前文件级备份（在 AppDatabase.getInstance 里、openHelper 触发之前）：
   只读方式打开旧库读 PRAGMA user_version；== 12 时把 zhiwo_shiguangjian / -wal / -shm
   三件套复制到 getDatabasePath(...).parentFile/"backups"/pre_v13_<ts>/
1) CREATE goals, plans（+ index_plans_goalId）
2) 读旧库：Cursor 遍历 records WHERE category='goal' → 逐条 Kotlin 生成 goal 行，
   同时内存保留 map<oldRecordId, newGoalId>
3) CREATE TABLE mig_task_src AS SELECT * FROM tasks   （快照，见 A.3.1 为什么必须先快照）
4) Kotlin 遍历 mig_task_src：LegacyTaskMapper.map(row, goalIdOf) → 
   INSERT INTO tasks_new(...) VALUES(...)   ← 逐行、参数绑定，不做字符串拼接
5) INSERT INTO mig_occ(taskId,date,status,...) 收集 mapper 产出的 occurrence
6) DROP TABLE tasks                       ← 此时无任何子表引用 tasks，不会级联
7) ALTER TABLE tasks_new RENAME TO tasks
8) CREATE INDEX index_tasks_recordId / goalId / planId
9) CREATE TABLE task_occurrences + 唯一索引   ← 引用已定型的 tasks
10) INSERT INTO task_occurrences SELECT ... FROM mig_occ
11) DROP TABLE mig_task_src, mig_occ
12) 自检：PRAGMA table_info(tasks) 必须含全部 22 列，缺列则抛 IllegalStateException
    （交给 ZhiwoApplication 既有的 rebuild() 兜底路径，见 A.6）
```

### A.3.1 为什么不能"直接 DROP 旧 tasks 再重建"
`task_occurrences` 若先建，`DROP TABLE tasks` 会因 `ON DELETE CASCADE` 在 SQLite 内触发隐式 DELETE，把打卡记录连带清空；而 `PRAGMA foreign_keys=OFF` 在事务内无效（Room 迁移在事务里跑）。所以固定顺序：**快照 → 建新表 → 填数据 → 删旧表 → 改名 → 最后才建子表**。这段必须写进代码注释，否则后人会顺手调整顺序。

### A.3.2 为什么映射放在 Kotlin 而不是纯 SQL
- `weekly → weekdaysCsv` 要 ISO 星期（SQL `strftime('%w')` 周日=0，转换易错且不可单测）；
- 旧 `dueDate` 混存了 `""`、`yyyy-MM-dd`、`yyyy-MM-dd HH:mm:ss`、ISO 带 `T` 四种格式，需要容错解析；
- **映射函数必须是纯函数才能写 JVM 单测**（这是本方案"可证伪"的地基）。DDL 用 SQL，逐行映射用 Kotlin。

## A.4 纯映射函数（`LegacyTaskMapper.kt`）

```kotlin
data class LegacyTaskRow(val id: Long, val content: String, val recordId: Long?, val parentGoalId: Long?,
  val dueDate: String, val taskType: String, val isCompleted: Boolean, val completedAt: String?,
  val dailyCompletionDate: String?, val isPermanentlyCompleted: Boolean, val calendarEventId: Long?, val createdAt: String)

data class MappedTask(val columns: Map<String, Any?>, val occurrences: List<MappedOccurrence>)

fun mapLegacyTask(row: LegacyTaskRow, goalIdOf: (Long) -> Long?, today: String): MappedTask
fun parseLooseDate(v: String): LocalDate?      // 4 种历史格式 + 空白 → null
```
映射规则（每条都要有测试，见 A.8）：
- `taskType` 未知值（含空串、大小写异常）→ `kind='adhoc'`，不抛异常。
- `daily` → `kind=daily, repeatRule=everyday, dayPolicy=all, startDate='', endDate=''`；`scheduledDate=''`。
- `weekly` → `kind=daily, repeatRule=custom, weekdaysCsv=ISO(dueDate 星期)`；`dueDate` 解析失败 → 退化 `repeatRule=everyday` 并记日志（**不得丢任务**）。
- `once` → `kind=adhoc, scheduledDate=parseLoose(dueDate) 或 ''`，`dueDate=''`（老数据只有"一个日期"，不臆造期限）。
- `goal` → `kind=adhoc`（里程碑），`goalId = goalIdOf(parentGoalId ?: recordId)`。
- `parentGoalId` 非空且能在 map 中找到 → `goalId=` 新 id；找不到（记录已被删的孤儿）→ `goalId=null`，不崩。
- 完成态：`isCompleted && dailyCompletionDate` 非空 → occurrence(date=dailyCompletionDate,done)；
  `isCompleted && 无 dailyCompletionDate` → occurrence(date=parseLoose(completedAt) 或 today, done)；
  `isPermanentlyCompleted` → 额外把 `status='archived'`（保住老语义"完成后不再每日刷新"）。
- `durationMinutes=0, remindTime='', colorIndex=0, sortOrder=0, createdAt` 原样带过去。

## A.5 DAO 约定

- 全部读接口返回 `Flow`（与现有 9 个 DAO 一致）。
- `TaskDao`：删 `getTasksByType`（现在无人调用）、`deleteTasksByParentGoalId`（无人调用）；新增 `getActiveTasks()`（`WHERE status='active'`）、`getTasksByGoalId/PlanId`、`getTasksForDateQuery` 交给 B 的引擎在内存筛（**不要在 SQL 里写重复规则判断**，那是引擎的活）。
- `TaskOccurrenceDao`：`getOccurrencesForDate(date)`、`getOccurrencesForTaskBetween(taskId,from,to)`、`upsert(entity)`（REPLACE）、`deleteById`、`getOccurrencesInRange(from,to)`（供评价/日记/进度）。
- `GoalDao`/`PlanDao`：`getActive`、`getById`、`insert/update/delete`、`getPlanCountByGoal`。
- **不做**分页/游标：私人自用数据量（任务数十条），全量 Flow 内存筛更简单；写进 ADR 避免被"优化"。
