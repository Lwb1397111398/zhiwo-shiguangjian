# 任务·目标·计划·记录·打卡 的演进路径与关系设计（2026-10-12）

> 起因：老板在安排页「彻底删除」了一条由记录转来的任务，记录立刻变回"杂项待办"，
> 而杂项行只有「勾选 / 转为任务」两个出口，没有删除——被卡死了。
> 排查后确认这不是孤立 bug，而是整套生命周期缺一份统一设计：同类死角还有 13 处（见 §五）。
> 本文是全量状态机的唯一出处，代码实现与本文冲突时以本文为准并修正代码。

## 一、五种数据，各自的身份

数据只有一条流向：**记录（老板写下的事实）→ 任务（要做的事）→ 打卡（某天做没做的结果）**；
**目标（长期方向）→ 计划（时间窗）→ 任务** 是另一条组织线。任务处在两条线的交点上。

| 实体 | 表 | 它是什么 | 它属于谁 |
|---|---|---|---|
| 记录 | records | 老板写下的原始素材，category 标性质 | 谁也不属于；它可以派生任务，但任务消失不影响它 |
| 任务 | tasks | "要做的事"的定义，status 标生死 | 可挂 goalId/planId（组织归属）、recordId（来源溯源），全部可为空 |
| 打卡 | task_occurrences | 某个任务在某天的结果（done/not_done/pending） | 唯一依附于任务的东西——任务物理删除时它跟着删（CASCADE），因为"没有任务的结果"无意义 |
| 计划 | plans | 一段时间窗 + 一组任务 | 挂 goalId，可自由 |
| 目标 | goals | 长期方向 | 独立；recordId 只作溯源、不建外键 |

**摘链不连坐（铁律）**：删除/终结任何实体，只断开指向它的引用（SET NULL / 手动摘链），
不牵连删除指向方的本体。唯一的连坐是 任务→打卡（定义与结果同命）。
这条在 v14 已写进外键（recordId/goalId/planId 全 SET NULL），本设计把没走外键的路径
（删计划手动摘链、删目标、删记录）也统一到同一语义，并保证**摘链后的每一条都有页面可见、有出口可走**。

## 二、状态机（演进路径）

### 2.1 任务（tasks.status）

```
                 ┌────────暂停────────┐
                 ▼                    │
   新建 ──► active ◄────────恢复────────┤ paused
              │    ◄────────恢复────────┤
              │                         └────（paused 由编辑器"暂停任务"进入）
              ├────────结束(归档)────────► archived ──恢复──► active
              │                            ▲
              │◄───恢复（总览页）────────────┘
              └───任意状态──彻底删除（安排页编辑器/总览页）──► 物理删除（打卡随删，确认框报数）
```

- 入口：active = 编辑器"保存"；paused = 编辑器"暂停任务"（**本轮补**，此前 paused 只有数据层没有 UI，是"谁也进不去的状态"）；archived = 编辑器"结束任务"（老"真正完成"的等价物，保史）。
- 出口：恢复在编辑器（paused→active）与总览页（paused/archived→active，**本轮补**——此前归档是单向门）；彻底删除两处都有。
- **adhoc 专属规则「判后了结」（本轮核心新增）**：临时任务是一次性事实，只要它出现过一条
  `done` 或 `not_done` 打卡（任意日期），引擎即视它"了结"，次日起不再出现在安排页任何段
  （当天仍如实显示✓/✗，让老板看到自己刚记下的结果）；`pending`（撤销完成）不算判决——
  撤销后任务回到安排页，保持可逆。了结**不改 status、不写库**：纯由打卡记录推导，
  这样归档语义（用户显式"结束"）不被污染，总览页仍按 active 可见可管理，撤销天然还原。

### 2.2 打卡（task_occurrences.status）

```
（无行）──勾选──► done ──撤销──► pending ──再勾选──► done
（无行）──长按记"没做"──► not_done ──撤销──► pending
```
- pending 是软标记不删行（用户填过的原因留着）；同一 (taskId,date) 永远一条。
- 撤销完成 = 唯一的"反悔"通道，安排页、记录页、日历页共用 bridge.uncheck。

### 2.3 记录（records.category 是分类不是生死）

```
任意类别 ──编辑改类──► 别的类别（含 completed=勾完成的软退出）
任意类别 ──删除记录（详情页 / 杂项行【本轮补】）──► 物理删除：派生任务摘链存活，闹钟不动
```
- **杂项待办不是一个状态**，是"category=todo 且当前没有任何任务挂 recordId"这个谓词拼出来的视图；
  它的进和出都只由（category、recordId 是否被占用）两个事实决定——所以派生任务被物理删除后
  记录回到杂项是**符合设计的**（记录本体没被删过）；问题在于此前这一视图没有给删除出口。本轮补：
  杂项行 = 勾选完成 / 转为任务 / **删除记录（带确认）** / **点击整行去记录详情**（路由早已接好，行没挂上）。
- 彻底删除任务时，若它挂着来源记录，确认框如实告知（**本轮补**）："这条任务来自记录《X》，
  删任务不会删记录，它会回到杂项待办，在那里可以直接删。"

### 2.4 计划（plans.status）

```
新建 ──► active ◄───暂停/恢复──► paused
            │（只能由目标结局级联进入）
            ├──目标达成──► done     ├──彻底删除计划──► 物理删除
            └──目标放弃──► dropped  └─（其下任务摘链成自由任务，打卡史整批保留）
```

### 2.5 目标（goals.status）

```
新建 ──► active ──达成──► achieved（级联：计划→done；daily/blank 任务→archived；adhoc 欠账坐实 not_done）
              └─放弃──► abandoned（级联同上，计划→dropped；归档走 bridge 补齐镜像【本轮修正】）
              └─彻底删除（【本轮补】：确认报数"其下 N 计划 M 任务将转为自由，不连带删除"；
                          plans.goalId、tasks.goalId 摘 NULL，总览页"自由块"兜底）
```

## 三、七条不变量（任何情况下系统必须满足）

1. **每一行可见项都有出口**：安排页每段、杂项行、总览页每行、编辑器，都不存在"看得到却做不掉"的行。
2. **终态可逆**：paused/archived 有恢复按钮；adhoc 的"判后了结"可撤销打卡还原；物理删除不可逆但确认框如实报数。
3. **单一事实源**：某天排不排 → 只问 `TaskScheduleEngine`；状态迁移的编排在 `data/repository/TaskLifecycle`（新增，安排页与总览页共用）；双写只走 `TaskWriteBridge`。任何页面/闹钟不得自判一套。
4. **闹钟只在"非 active 或无提醒时间"时停**（注册侧 gate 兜底，触发侧 `ReminderGate` 再挡当天已完成）。勾选完成**不停铃**——否则每日任务今天勾一次，明天就永远不响（本轮修掉两处"勾完成顺手 cancelAlarm"）。
5. **摘链不连坐**（§一铁律），删除路径 = 摘链 + 删本体，绝不静默删别人的历史。
6. **每条归属都在至少一个页面可见**：总览页"自由块"兜住所有指向空/失效的行（既有设计，本轮新增入口继续遵守）。
7. **没数完不许确认**：涉及物理删除的确认框，先数出连带条数再允许按"确认"（既有设计，新入口沿用）。

## 四、关系断开矩阵

| 操作 | 本体归宿 | 指向它的引用怎么处理 | 历史（打卡） | 闹钟/日历事件 |
|---|---|---|---|---|
| 彻底删除任务 | 行删除 | occurrences **CASCADE 随删** | 随任务删，确认报数 | 删前 cancelAlarm + 删日历事件 |
| 删除记录 | 行删除 | 派生任务 recordId=NULL 摘链 | 不动 | **不动**（任务还活着还得响；本轮修正两处误停） |
| 记录转记忆（整理） | 行删除→写 memory | 派生任务摘链存活 | 不动 | **不动**（本轮修正：原来把存活任务的铃停了） |
| 彻底删除计划 | 行删除 | 其下任务 planId/goalId=NULL 转自由 | 整批保留 | 不动 |
| 彻底删除目标（新增） | 行删除 | 计划 goalId=NULL、直属任务 goalId=NULL 转自由 | 不动 | 不动 |
| 目标达成/放弃 | status 终态 | 计划 done/dropped；daily/blank→archived；adhoc 欠账补 not_done 坐实 | 追加记录 | 全部 cancelAlarm |
| 任务结束(归档) | status=archived | 无 | 保留，随时可查 | cancelAlarm |
| 任务暂停 | status=paused | 无 | 保留 | cancelAlarm（恢复时重新注册） |
| adhoc 判后了结 | status 不变 | 无（纯引擎推导） | 那条判决记录本身 | 无（一次性闹钟当天响完自然消失；触发时 gate 已挡） |

## 五、本轮堵住的 14 个坑（编号→修复）

| # | 坑（现状证据） | 修复 |
|---|---|---|
| B1 | 删任务→记录回杂项、杂项无删除入口（老板报的） | 杂项行加"删除"（确认）+点击行去记录详情；删任务确认框提示来源记录（§2.3） |
| B2 | adhoc 勾完成，次日 occ 日期对不上，重回"已过期"永驻 | 引擎判后了结（§2.1）；MFD07 旧断言按新语义改写 |
| B3 | archived/paused 的 adhoc 仍显示在"已过期"（过期分支先于状态检查） | 引擎 adhoc 分支先过 active 门控 |
| B4 | 目标达成/放弃后，其下未判决 adhoc 永驻"已过期" | B3 门控 + goalStatus 非 active 拦截；finishGoal 坐实的 not_done 同时触发判后了结 |
| B5 | 无 scheduledDate 无期限的 adhoc 永驻"临时·今天"，勾完次日复活 | 判后了结覆盖（无日期任务任何判决即了结） |
| B6 | archived 任务全 App 无恢复入口（单向门） | 总览页任务行加"恢复"；"结束/删除"仍走原路径 |
| B7 | paused 状态无任何 UI 入口 | 编辑器加"暂停任务"按钮（active 时显示）；总览页"已暂停"可恢复 |
| B8 | finishGoal 放弃分支裸 updateTask 绕过 bridge，少镜像 isPermanentlyCompleted | 统一走 bridge.archive |
| B9 | 日历页"真正完成"归档后不停闹钟（僵尸铃，靠 gate 静默+下次开机才清） | 归档路径补 cancelAlarm |
| B10 | 删记录/记录转记忆时误停**存活任务**的闹钟（daily 从此哑火到下次重启复活） | 摘链保留任务的路径一律不动闹钟 |
| B11 | 记录页/日历页勾完成后 cancelAlarm，每日任务明天不响 | 勾完成不停铃（不变量 4）；当天误响由 ReminderGate 挡 |
| B12 | 目标无物理删除入口（GoalDao.deleteById 是死代码） | 目标详情页加"删除目标"：摘链转自由、确认报数 |
| B13 | scheduled 与 deadline 之间被引擎判"已过期"，与字段文档口径和 `adhocOverdueOn` 矛盾（两套判据并存） | 引擎统一：窗口内=待做、过期限才过期；判过期用 `adhocOverdueOn` 同一条规则 |
| B14 | 死代码 deleteTasksByRecordId（CASCADE 时代遗留）、deleteByGoal 误导后人 | 删除；保留并启用 detachFromGoal 供删目标用 |

## 六、实现落点（文件级）

- 排期判定：`data/tasks/TaskScheduleEngine.kt` adhoc 分支重写（了结=入参 occurrences 里存在 done/not_done；纯推导不写库）；调用方把"完整打卡窗口"交给引擎自己过滤当日——`ScheduleViewModel` 观察范围从 30 天放宽为全量、`CalendarViewModel`/`TaskSummaryBuilder` 不再预过滤。
- 迁移编排唯一出处：`data/repository/TaskLifecycle.kt`（新增）——changeStatus / deleteForever，安排页与总览页共用；桥接与闹钟纪律不变。
- UI 出口：`ScheduleScreen`（杂项行、删任务确认、编辑器暂停）、`PlansOverviewScreen`（恢复/删除按钮+确认）、`GoalDetailScreen`（删除目标+确认）。
- 一致性小修：`GoalDetailViewModel`（B8 归档镜像、B4 逾期计数并判后口径）、`CalendarViewModel`/`RecordListViewModel`（B9/B10/B11 停铃规则）、`RecordOrganizer.applyToMemory`（B10）。
- DAO 卫生：`TaskDao.detachTasksFromGoal`（新增）、删 B14 死代码；**无 schema 变更，数据库版本仍 14，不需要迁移**。
