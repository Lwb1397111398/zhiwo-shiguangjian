## 0. 一句话

把「任务只是记录的附属」改成 **目标 → 计划 → 任务 → 每日打卡** 四层真对象；任务分**每日固定 / 临时一次 / 每日留白**三 kind，支持起止日期、重复规则、工作日/节假日策略、指定哪天出现、未做即过期、完成/未完成带原因；记录页「安排」重排为分段视图并**首次提供手动新建任务/计划/目标的入口**；同时修掉记忆「一键整理后总有残存」的 7 个成因。

## 2. 数据模型（v13 增量 + v14 定型）

### 2.1 新表
- `goals(id, title, description, startDate, targetDate, status[active|achieved|abandoned], recordId, sortOrder, createdAt, updatedAt)` —— `recordId` **不设 FK**（删记录不牵连目标）。
- `plans(id, goalId→goals SET NULL, title, description, startDate, endDate, status[active|paused|done|dropped], recordId, sortOrder, createdAt, updatedAt)`
- `task_occurrences(id, taskId→tasks CASCADE, date, status[done|not_done], reasonCode[no_time|tired|sick|forgot|changed|skipped_blank|other], reasonNote, actualMinutes, note, createdAt, updatedAt)` + 唯一索引 `(taskId,date)`（**upsert 由代码 merge 保证，不用 REPLACE**）
- `day_overrides(date PK, type[workday|holiday], createdAt)` —— 用户把某天手标班/休，优先级最高。

### 2.2 `tasks` 新增列（v13 `ALTER TABLE ADD COLUMN`，全部带 DEFAULT，老列一律保留）
`kind[daily|adhoc|blank] DEFAULT 'adhoc'`、`repeatRule[everyday|weekdays|custom|interval] DEFAULT 'everyday'`、`weekdaysCsv DEFAULT ''`、`intervalDays DEFAULT 1`、`dayPolicy[all|workday_only|holiday_only] DEFAULT 'all'`、`startDate DEFAULT ''`、`endDate DEFAULT ''`、`scheduledDate DEFAULT ''`、`remindTime DEFAULT ''`、`durationMinutes DEFAULT 0`、`goalId`(FK→goals SET NULL)、`planId`(FK→plans SET NULL)、`status[active|paused|archived] DEFAULT 'active'`、`colorIndex DEFAULT 0`、`sortOrder DEFAULT 0`
- v13 存量回填（一次性，同一迁移内）：按 §2.4 映射规则从 `taskType/isCompleted/dailyCompletionDate/isPermanentlyCompleted/parentGoalId/dueDate` 算出新列值并写入；老列随后由"双写"保持同步，老 UI 继续可用。
- v14：重建 `tasks` 删掉 6 个老列 + `recordId` FK 改 SET NULL。重建序列见 §7 A4（含"occurrence 计数前后必须相等"守卫，原因：`DROP TABLE tasks` 会经 CASCADE 连带清空打卡史）。

### 2.3 语义约定
- 日期列一律 `yyyy-MM-dd` 文本，空串=未设置；**禁止**再存 `yyyy-MM-dd HH:mm:ss`（旧 `dueDate` 混格式才是 `SUBSTR(x,1,10)` 满天飞的根源）。
- "今天"= 设备本地日历日（`DateFormats.nowDate()`，DateFormats.kt:13）。**日切按自然日 00:00**；不搞"凌晨 4 点算昨天"这种魔法，改为**打卡/回填时可显式选择归属日期**（默认今天，可往前调 7 天）—— 覆盖"夜里 12 点半跑完步"的场景且行为可预测。
- `dueDate` 的过期判定**只看日期部分，忽略时间**（旧数据里 `dueDate` 带时间，必须钉死这条）。
- 提醒：`remindTime` 是任务开始时刻；实际响铃 = `remindTime - 15min`（沿用 `SmartScheduleManager.kt:16 REMIND_MINUTES_BEFORE`）；系统日历事件时长用 `durationMinutes`（>0 时）否则用现有 `EVENT_DURATION_MILLIS`。

### 2.4 存量映射（`LegacyTaskRow` 独立 DTO，**不用 TaskEntity 当输入**）
| 旧 | 新 |
|---|---|
| `taskType='daily'` | `kind=daily, repeatRule=everyday, dayPolicy=all` |
| `taskType='weekly'` | `kind=daily, repeatRule=custom, weekdaysCsv=ISO(dueDate 星期)`；解析失败 → `repeatRule=everyday` + 记 issue（**不丢任务**） |
| `taskType='once'` | `kind=adhoc, scheduledDate=parseLoose(dueDate)`；为空则 `''`（=从创建日起持续出现直到完成） |
| `taskType='goal'` | `kind=adhoc`（里程碑），`goalId` 按 §2.4 末行挂到 goal |
| **旧 `dueDate` 含时间**（`2026-09-24 09:00:00`） | **`remindTime='09:00'`**（v1 漏了这条 → 迁移后每日提醒会集体消失，是评审 A-MF4(a)） |
| `isCompleted=1` 且 `dailyCompletionDate` 非空 | occurrence(`date=dailyCompletionDate, done`)，**且只产出一条**（不再叠加 completedAt 分支，v1 两条规则重叠是评审 A 指出的双写风险） |
| `isCompleted=1` 且 `dailyCompletionDate` 为空（含 weekly 的完成态） | occurrence(`date=date(completedAt) 或 today, done`)（v1 漏：weekly 的完成历史无处映射） |
| `isPermanentlyCompleted=1` | 上述之外再置 `status='archived'`（保住老语义"完成后不再每日刷新"）；新模型出口＝编辑器「结束任务」 |
| `parentGoalId` 非空 | 查 `oldRecordId→newGoalId` 映射表；孤儿（记录已删）→ `goalId=null` + 计入"未能识别"报告 |
| **所有 `category='goal'` 的记录**（不只被 parentGoalId 引用的） | **每个都建一行 goal**（v1 只从被引用的建 → 现存没有子任务的目标会整条丢失，评审 A-MF4(c)） |
| `category='todo'` 且无任何任务的记录 | **不转成任务**（评审 A-MF5）：安排页保留可隐藏的「杂项待办（来自记录）」过渡段 + 行内「转为任务」按钮，不批量改写用户数据 |

映射函数必须是纯函数并返回 `(rows, List<MigrationIssue>)`，**禁止用 filter 静默丢行**；`legacyRowsToJson/jsonToLegacyRows` 往返必须相等（含中文/emoji/换行/null）。

## 3. 排期引擎（唯一真相源）

规格自洽性先把 v1 的 5 处矛盾钉死（评审 B-S1..S5）：
- `entriesFor(date, tasks, occurrences, dayType, parentStatusById, sourceNames)` 保证：**每个任务至多产出一条** `DayEntry`；`paused/archived` 任务**不产出**（不设 `PAUSED/ENDED` 枚举，避免死枚举）；"未到期"的 adhoc **不产出**（不设 `UPCOMING` 进日计划；改由「即将开始」折叠视图单独调 `upcomingAdhoc(tasks, date)`）。
- 枚举与页面段一一对应：`EntrySection = DAILY_FIXED | DAILY_BLANK | ADHOC_TODAY | MISC_TODO | OVERDUE | MISSED | DONE_TODAY | UNFILLED`；`EntryState = DUE | DONE | NOT_DONE | OVERDUE | UNFILLED`。
- `interval` 锚点：`startDate` 非空用它，否则用 `date(createdAt)`，都非法 → 该任务不产出 + 记 issue；`intervalDays < 1` 按 1 处理（=每天）并记 issue。
- `weekdaysCsv` 为空 + `repeatRule='custom'` → 按 `everyday` 处理并记 issue；`repeatRule='weekdays'` 与 `weekdaysCsv` 同时有值 → **以 repeatRule 为准**；脏值（`0`/`8`/`1;3`/`''`）逐条定义（忽略非法项，全非法→everyday）。
- `weekdays`（看星期）与 `dayPolicy`（看是否上班日）**取交集**，并有一条专门用例钉死"周六补班 + repeatRule=weekdays + workday_only"该不该出现（答案：不出现，`weekdays` 字面即周一至周五）。
- 排序键固定为 `section → sortOrder → id`；`dueCount/doneCount` 口径：分母只算当天 `entriesFor` 产出且 section ∈ {DAILY_FIXED, DAILY_BLANK, ADHOC_TODAY, MISC_TODO} 的条数，`MISSED/UNFILLED/OVERDUE` **不入当天分母**（缺口单独计数，避免"昨天没做把今天完成率也拉低"）。
- `progressOf(tasks, plans, goals, occurrences, overrides, from, to)` 显式带全部分母来源；`to-from > 366` 天截断并标注；**同一任务同时挂 goalId+planId 时只计入 plan**（否则目标进度双算虚高，评审 B-36）。
- 纯函数纪律：引擎文件内 `grep -c "LocalDateTime.now()\|LocalDate.now()\|Calendar.getInstance()\|import android"` == 0；不得调 `Log`（问题以 `List<String>` 返回），因为 `app/build.gradle.kts` 未开 `isReturnDefaultValues`，碰 `Log` 的分支在 JVM 必抛 not-mocked。

新增能力（评审 A-MF8、B-41）：
- `missedOn(from, to)`：区间内"排期成立但当天无任何 occurrence"→ 进「待补录」段，支持补打卡/补填原因；daily/blank 都有漏做概念，不再只有 adhoc 会"过期"。
- 「待回填」（blank 未填）窗口只列**最近 7 天**，更早的自动折叠进"更早 N 条"，防止段无限变长。

## 5. 节假日数据（C3 的正面回答）

1. 优先级：`day_overrides`（用户标记）> `HolidayCalendar` 内置公告数据 > 周一至周五=WORKDAY。
2. 内置数据形态：`HolidayCalendar.kt` 内按年分节的两个日期集合（放假日、调休上班日）。**录入纪律**：实现时联网查《国务院办公厅关于 X 年部分节假日安排的通知》原文核对后写死，文件头注明来源链接与录入日期；查不到的年份**留空**并在设置页显示"该年按周末判定"。当前只录 2026（2027 公告通常年底才出）。
3. UI 入口：日历页长按某天 → 「标为工作日/休息日/恢复默认」。
4. `SpecialDateEntity`（生日/纪念日）与 `FestivalProvider`（节日名）**不参与**判定，并有防回归用例：某人生日不能让那天变 HOLIDAY。

## 6. 记忆残存修复（7 成因，详见 40-小计划E-v2）

R1 整理从不物理删记忆 / R2 superseded 仍显示在"已更正"折叠区且无删除入口 / R3 整句全等判重放过近义 / R4 上一批 PENDING 永不可见永不执行 / R5 dismiss 不清下游依赖致 DELETE 永久 BLOCKED / R6 每条删除提案携带全部所选 id（勾 1 删全部）/ R7 记忆合并拆分两套互不相通实现（一套硬删无事务）。
v2 补充的前置（评审 A-MF10）：**R6 依赖 AI 契约改造** —— `classify/smartClean` 现在只回字符串标签（AiRepository.kt:428-482、AiPrompts.kt:185-210），必须先把 prompt+模型+parser 改成输出 `{text, sourceIds[]}` 并把 label 反查换成 id 直传，否则实施时最省事的"修法"仍是删全集。
新增 op 类型 `MERGE_MEMORY/SPLIT_MEMORY/DELETE_MEMORY` 必须**同时**登记进 `OpPayloads.kt` 的 `executionOrder()` 与 `OpValidator.decide`（否则 planBatch 排序与双双失效）。
语义统一：整理只 `superseded`；物理删除只发生在用户显式点"彻底删除"或 superseded 超 30 条的自动清理；`getMemoryCount` 只数 active；`memories` 加 `occurredAt` 列（createdAt 用真实写入时间，避免"刚整理的记忆因 createdAt 老被上限挤掉"）。

## 9. 数据与回滚防线（迁移安全，评审 B-MF8）

1. **同步化打开**：`ZhiwoApplication.onCreate` 改调 `DatabaseBootstrap.ensureDatabaseReady()`（同步：open 失败即备份+rebuild 一次做完），杜绝"某个 ViewModel 先抛 → 进程被杀 → 下次重来 → 崩溃循环且永远不生成备份"。
2. **迁移前整库文件级备份**：以只读方式取 `PRAGMA user_version`，<13 时把主库+`-wal`+`-shm` 三件套复制到 `getExternalFilesDir("migration_backup")/pre_v13_<ts>/`（v14 同理 `pre_v14_`）。
3. **备份自证**：迁移内写出 tasks 全表 JSON → **回读** → 断言行数 == 老表 `COUNT(*)`，失败即抛（不静默）。
4. **迁移后自检**：新 `tasks` 行数 == 老行数、`task_occurrences` 计数符合映射函数预期，不等即抛。
5. **v14 特殊守卫**：重建 `tasks` 前后 `task_occurrences` 计数必须相等（`DROP TABLE tasks` 会经 CASCADE 连带清空打卡史）→ 采用 `PRAGMA legacy_alter_table=ON` + RENAME 序列；不等则抛并回滚。
6. **失败横幅**：`MIGRATION_FAILED` 标记落 settings，设置页顶部亮横幅「上次迁移失败，数据已备份为 X，点这里重试」。
7. **回滚入口**：设置页「恢复到升级前」→ 关闭 DB、还原 `pre_v13_*`（或 `pre_v14_*`）三件套、重启进程。**明确不实现通用 JSON 导入**（本轮不做，措辞从"可回溯"改为"文件级回滚，仅覆盖迁移前一刻"）。
8. **备份只在 release/debug 均生效**（因为 ①去掉了 debug 破坏性兜底）。老板现有习惯是装 debug 包，所以这条必须先改代码再谈迁移。

## 12. 环境事实（开工前置，P0）

- 项目路径含中文造成两重故障：AGP 拒建（已用 `android.overridePathCheck=true` 跳过）；**Kotlin 守护进程/测试 worker 把中文路径转义成 `u77E5u6211...`** → 插件 classpath 与 test worker classpath 全部 not found。解法：Gradle Home 与 `java.io.tmpdir` 都放 ASCII 路径（`E:/AI Agent/zhiwo-gradle-home`、`E:/AI Agent/tmp`），已实测编译通过；测试 worker 结果见 `01-评分记录.md` P0 一节。曾试 ASCII junction 指向项目目录 → 无效（Gradle 会规范化回真实路径）。
- 上述解法只是"能跑起来"，**必须在 §文档里写死构建命令**，否则下一次会话又会踩一遍。若 tmpdir 方案仍不能跑通测试，退路是把项目整体移到 ASCII 路径（属破坏性变更，须先问老板）。
