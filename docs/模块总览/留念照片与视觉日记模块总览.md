# 留念照片与视觉日记模块总览

## 模块职责（一句话）

任务打卡完成后自愿拍/选一张「留念照」，照片按天归档进日记；配置了识图模型时，AI 写日记和每日评价会真的看图点评（如「哇，这座桥真漂亮」）。

## 运作流程

1. **入口**：安排页任务勾完成 → 行尾出现绿色 📸 按钮（只对已完成行显示）；点它先弹「拍照 / 从相册选 / 先不用」。日记页阅读某天日记时，正文下方照片条末尾有「补一张」格子，同样入口。
2. **拍照路**：`rememberMomentPhotoHost`（ui/components/MomentPhotoUi.kt）生成空文件 `filesDir/photos/IMG_时间戳.jpg`，经 FileProvider（`file_paths.xml` 的 `moment_photos`，authorities=`com.zhiwo.shiguangjian.fileprovider`）把 URI 交给系统相机直写。不用相机权限；手机没有相机应用时自动退到相册。取消拍摄/拍到 0 字节文件就地删除，不入库。
3. **相册路**：Android Photo Picker（`ActivityResultContracts.PickVisualMedia`，免存储权限），选中的 URI 解码降采样到长边 ≤1600、JPEG 85，复制进私有目录。
4. **入库**：`MomentPhotoRepository`（data/photo/）先走 `MomentPhotoStore.compressInPlace` 把相机原图压到同规格，再写 `moment_photos` 表一行（date/path/label/source/createdAt）；写库失败会把它落下的文件删掉。照片存的是应用私有目录（卸载即清，不进公共相册，无需存储权限）。
5. **展示**：日记页阅读视图按天拉照片流（Room Flow 随存随变），横排 88dp 缩略图 + 删除角标（删行必删文件）。
6. **喂给 AI**：写日记/每日评价时（含重生成），ViewModel 取当天照片，转成 OpenAI 识图格式 data URL（长边 ≤1024、JPEG 78），最多 4 张（`MAX_AI_PHOTOS`，防请求体爆炸）；同时把「今天拍了 N 张留念照片（「任务名」）」写实说明注入 prompt。**只有设置页开了「模型支持识图」开关才会真的附图**——没有任何办法自动探测远端模型吃不吃图，乱发 `image_url` 会被不支持的接口直接拒收，所以开关默认关。
7. **消息格式**：`AiRepository.chatOnce` 在 visionEnabled 且带图时，把最后一条 user 消息的 content 从纯文本换成 `[{type:"text"},{type:"image_url"}...]` 部件数组（OpenAI 多模态格式）；其余消息和未开开关时完全不变。带图请求失败的重试策略与纯文本相同（指数退避 2 次）。

## 入口文件清单

- `data/db/entity/MomentPhotoEntity.kt` — 表实体（moment_photos，v15 新增）
- `data/db/dao/MomentPhotoDao.kt` — 按天查询/插入/删除
- `data/db/Migration14To15.kt` — v14→v15 纯建表迁移（IF NOT EXISTS，半途失败重跑不炸）
- `data/photo/MomentPhotoStore.kt` — 文件侧：落盘路径、压缩降采样、data URL 转换
- `data/photo/MomentPhotoRepository.kt` — DB 行与文件同进退的统一入口 + AI 取图
- `ui/components/MomentPhotoUi.kt` — 拍照/选图 host、选择对话框、缩略图组件（安排页与日记页共用）
- `data/ai/AiRepository.kt` — chat 带图门控（visionEnabled）+ generateDiary/generateDailyReview 的 photoUrls/photosNote 参数
- `data/ai/AiPrompts.kt` — `{{photo_hint}}` 占位（点评指令：只许写照片里看得见的，禁止编细节）+ 语气调整（更有活力、温柔温暖）
- `ui/screens/ScheduleScreen.kt` — 完成行 📸 按钮与选择对话框
- `ui/screens/DiaryScreen.kt` — 阅读视图照片条 + 「补一张」
- `ui/screens/SettingsScreen.kt` + `ui/viewmodel/SettingsViewModel.kt` — 「模型支持识图」开关（settings 表 key=`supportsVision`，"1"/"0"）

## 对外接口 / 被谁调用

- `ZhiwoApplication.momentPhotoRepo`：全局单例，ScheduleViewModel / DiaryViewModel / ReviewViewModel / DiaryRegenerator 各取一份引用。
- `AiRepository.generateDiary / generateDailyReview` 新增两个带默认值的参数（photoUrls、photosNote），旧调用点无需改动即为纯文本行为。
- 数据库版本从 14 升到 15（AppDatabase.VERSION 唯一出处），失败页文案自动显示「从 14 升到 15」。

## 依赖的上游模块

- 数据层（Room v15）、AI 集成（chat/completions）、日记生成链（ReviewViewModel 自动日记 / DiaryRegenerator 重生成）。
- AndroidX Activity Result（TakePicture / PickVisualMedia）、FileProvider（androidx.core）。

## 关键数据结构

`moment_photos` 表：`id` PK 自增 / `date` "yyyy-MM-dd"（有索引，非唯一——一天可多张）/ `path` 绝对路径 / `label` 关联任务名或"手动补拍" / `source` camera|gallery / `createdAt` ISO 时间戳。

## 已知坑与约束

- **识图开关不会自动探测**：用户配了不支持识图的模型又开了开关 → 带图请求被 API 拒收，报错原样给界面，靠开关文案提示自查。
- 照片不迁移不备份：`filesDir/photos/` 不在 Room 库里，数据库备份/导出（ExportDataBuilder）不包含照片文件；删日记不删照片（照片是独立纪念），删照片会连文件一起删。
- 单测环境（本机）`testDebugUnitTest` 全部 ClassNotFoundException，cleanTest 无效——测试类编译成功但运行器加载不到，属既有环境问题，与照片功能无关；迁移正确性靠 `app/schemas/.../15.json` schema 对账（已生成并核对）。
- 语气与照片点评的效果没有度量指标，属于"未实测，需老板真机体验后反馈"。
