## B.2 引擎契约（唯一真相源）

```kotlin
enum class DayType { WORKDAY, HOLIDAY }
enum class EntrySection { DAILY_FIXED, DAILY_BLANK, ADHOC_TODAY, MISC_TODO, OVERDUE, MISSED, DONE_TODAY, UNFILLED }
enum class EntryState { DUE, DONE, NOT_DONE, OVERDUE, UNFILLED }

data class DayEntry(val task: TaskEntity, val occurrence: TaskOccurrenceEntity?,
                    val state: EntryState, val section: EntrySection, val sourceLabel: String?)

data class DayPlanResult(val entries: List<DayEntry>, val sections: Map<EntrySection, List<DayEntry>>,
                         val dueCount: Int, val doneCount: Int, val issues: List<String>)

fun dayTypeOf(date: String, holidays: Set<String>, makeupWorkdays: Set<String>,
              overrideType: String?): DayType
fun isScheduledOn(task: TaskEntity, date: String, dayType: DayType,
                  parentStatusById: Map<Long, String> = emptyMap()): Boolean
fun entriesFor(date: String, tasks: List<TaskEntity>, occurrences: List<TaskOccurrenceEntity>,
               dayType: DayType, parentStatusById: Map<Long, String> = emptyMap(),
               sourceNames: Map<Long, String> = emptyMap(),
               miscTodoRecords: List<RecordEntity> = emptyList()): DayPlanResult
fun upcomingAdhoc(tasks: List<TaskEntity>, date: String): List<TaskEntity>
fun missedOn(tasks, occurrences, from: String, to: String, dayTypeOf: (String) -> DayType): List<MissedItem>
fun isEffectivelyDone(task, occurrence, date): Boolean
fun unfilledBlanks(tasks, occurrences, today: String, windowDays: Int = 7): List<UnfilledItem>
fun streakOf(taskId: Long, occurrences: List<TaskOccurrenceEntity>, today: String, dayTypeOf: (String)->DayType): Int
fun progressOf(tasks, plans, goals, occurrences, overrides, from, to): Map<OwnerId, Progress>
```
硬保证（写进 KDoc 并用例断言）：
- G1 每个 task 在一次 `entriesFor` 中至多产出一条；结果无 null 元素。
- G2 无副作用：同入参两次调用结果 `==`；不修改入参列表。
- G3 排序键固定 `section 声明顺序 → sortOrder → id`。
- G4 `status != "active"` 的任务不产出（不设 PAUSED/ENDED 状态枚举）。
- G5 未到期 adhoc 不产出（`upcomingAdhoc` 单独取），避免 v1"既不出现又有状态"的矛盾。
- G6 分母 `dueCount` 只含 DAILY_FIXED/DAILY_BLANK/ADHOC_TODAY/MISC_TODO；OVERDUE/MISSED/UNFILLED/DONE_TODAY 不入分母（DONE 单列计数，完成率 = doneCount/(dueCount) 里已完成的部分按 `done 且属于今天` 口径，UI 显示 `已完成 X / 应做 Y`）。
- G7 解析失败一律"不产出 + 写进 `issues`"，绝不静默当今天、绝不抛异常。

## B.3 规则（v1 §B.3 全部保留，以下为 v2 增补/改法）

- **R-S3 interval 锚点**：`startDate` → 否则 `date(createdAt)` → 都非法则不产出 + issue。`intervalDays < 1` 按 1 处理 + issue。
- **R-S4 双归属不双算**：`planId != null` 时该任务只计入 plan 的 progress；只有 `planId == null && goalId != null` 才计入 goal。goal 的进度再按"其下 plan 进度 + goal 直属任务进度"合并。
- **R-S1/S2 段与状态对齐**：删掉 v1 的 `TaskState.PAUSED/ENDED/UPCOMING`、`DONE_TODAP` 拼写。
- **R-新 归属日期（跨零点）**：`setCheck(taskId, date, ...)` 的 `date` 由 UI 显式传入，默认今天，允许 `[today-7, today]`。引擎不理解"现在几点"。
- **R-新 漏做 MISSED 段**：`missedOn` 只回看最近 30 天；`MISSED` 与 `OVERDUE` 互斥（adhoc 走 OVERDUE，daily/blank 走 MISSED），同一条只出现在一个段。
- **R-新 UNFILLED 窗口**：只列最近 7 天，更早聚合为"更早 N 条"。
- **R-新 streak 定义**：连续"应做日"打卡数；被 `dayPolicy`/`repeatRule` 跳过的日子**不打断**连续（用例钉死），遇到"应做但没做"才归 1。
- **R-新 parentStatusById**：任务所属 plan/goal 非 active → 不产出。B 就用带 `paused` plan 的用例测掉，D 阶段只是开始传真值（避免"D 改完打破 B"）。
- **R-新 miscTodoRecords**：`category='todo'` 且无任务的记录以 `MISC_TODO` 段进入日计划（v2 §2.4 的过渡段），只读展示 + 「转为任务」由 C2 实现。

## B.4 节假日（与 v1 相同，措辞收紧）

优先级 `overrideType` > 内置 `holidays/makeupWorkdays` > 周一至周五。内置数据录入纪律：**联网核对国务院办公厅公告**，文件头写来源与录入日期，查不到的年份留空并由设置页显示"该年按周末判定"；`FestivalProvider`（节日名）与 `SpecialDateEntity`（生日/纪念日）**不参与**判定，并有防回归用例（某人生日不能让那天变 HOLIDAY）。
