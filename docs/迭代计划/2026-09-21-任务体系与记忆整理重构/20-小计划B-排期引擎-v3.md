## B.2 引擎契约
以总体方案 v3 §3 的签名块为准（`DayEntry` sealed、`DayPlanResult{planned,done,extra,dueCount,doneCount,issues}`、两个 status map、`HolidayResolver` 供 `DayType`）。追加实现约束：
- `entriesFor` 内部**必须**按 `occurrence.date == date` 过滤后再按 taskId 建索引（调用方会给跨天集合，用于 missedOn/summary 一并计算）。
- `miscTodoRecords` 产生的 `FromMiscRecord` 一律 `state=DUE`、`sourceLabel=null`、只进 `MISC_TODO`；G1 对它单独成立（一条记录至多一条）。
- 一切脏值回退都产生 `issues` 条目，文案含 taskId 与原值。

## B.3 判定规则（沿用 v2 §B.3，v3 修订点）
- R5（daily 重复）：`custom` + 空 `weekdaysCsv` → `everyday` + issue；`interval` 锚点 `startDate → date(createdAt) → 无锚点则不产出 + issue`；`intervalDays<1` 按 1 + issue。
- R6（dayPolicy）与 R5 **取交集**；周六补班 + `repeatRule=weekdays` + `workday_only` → **不出现**（`weekdays` 字面即周一至周五）。
- R9-R14（adhoc）：`dueDate < scheduledDate` → 判 `OVERDUE`（期限已过优先）；`scheduledDate==date` 且 `dueDate==date` → DUE；完成判据用 C-3 的统一函数。
- R15-R18（blank）：`UNFILLED` 只回看 `UNFILLED_WINDOW_DAYS`；「跳过」写 `not_done + reasonCode=skipped_blank`。
- R19-R22（打卡）：`setCheck` 事务；撤销=软 `pending`（C-5）；`actualMinutes` 与 `durationMinutes` 互不覆盖（0 不覆盖非 0）。
- R23-R24：日切为设备本地自然日；`date` 由调用方传入，UI 用 `produceState` + `applyPeriodicRestartInMillis(60_000)` 做分钟级重算（分钟级判据见 C1 v3 §C1.4）。

## B.4 节假日（v3 收紧）
1. 优先级：`day_overrides` > 内置公告数据 > 周一至周五。
2. **无数据年份不再静默降级**：`entriesFor` 对 `dayPolicy != "all"` 且该年无内置数据的任务 → **不产出**并写 issue（`HOLIDAY_DATA_MISSING`），由设置页横幅 + 安排页尾部计数提示；有数据后才参与判定。（v2 的"按周末兜底"会在国庆把 `workday_only` 任务照常安排并响铃，且与用户"根据节假日调整"的意图相反。）
3. 内置数据录入纪律：实现时联网取《国务院办公厅关于 2026 年部分节假日安排的通知》原文，把日期表写进 `docs/迭代计划/…/节假日公告-2026.md`，`HolidayCalendar.kt` 文件头引用该文件 + `holidayVersion` 常量；**公告未出的年份不填**。单测的期望值从公告原文推导（含 `2027-02-06` 除夕属 2027 春节、`2026-09-27` 补班属 2026 判定）；无 2026 数据时相关测试**编译期失败**（评审建议的 `require(HolidayCalendar.holidaysOf(2026).isNotEmpty())` 放 object 初始化）。
4. `FestivalProvider` 与 `SpecialDateEntity` 不参与判定，用例 MF-C07 防回归。
5. 2027 公告未出期间 `workday_only` 任务在 2027 长假会**不出现**（因数据缺失而整条隐藏）——这是 §2 的结果，必须在设置页横幅与实测清单里明写「该年无节假日数据，含节假日策略的任务已停用」，不能让用户以为任务丢了。
