# 任务与排期模块总览

## 职责一句话
把"目标 → 计划 → 任务 → 每日打卡"这套东西的定义与"今天该做什么"的计算，收在一处实现。

## 运作流程（数据从哪来 → 怎么处理 → 产出什么 → 影响谁）
1. **进来**：用户在安排页右上角 `+` 建任务（`ScheduleScreen.kt` 的 `TaskEditorSheet`），或由记录页 AI 抽取自动建（`InputViewModel.kt:156-166`，走的是老 `taskType` 字段）。
2. **落库**：一律经过 `TaskWriteBridge`（`data/repository/TaskOccurrenceRepository.kt` 文件内）。它同时写两套：新列（真值，`tasks.kind/repeatRule/…` 15 个字段）和老列（`taskType/isCompleted/dailyCompletionDate`，供还没改造的闹钟、开机恢复、日历页继续读）。反向也写：只填新字段时，桥接会用 `kind + scheduledDate + remindTime` 合成老列的 `taskType` 和带时间的 `dueDate`，否则 `SmartScheduleManager`/`BootReceiver` 读不到时间，用户新建的任务不会响铃。
3. **打卡**：`TaskOccurrenceRepository.setCheck()` 是 `task_occurrences` 的唯一写入口。先按 `(taskId,date)` 查，有则合并字段再 UPDATE，无则 INSERT —— 不用 `REPLACE`（自增主键下 `REPLACE` 根本不幂等，见 `LegacyTaskMapper` 注释与 `AppDatabase` 迁移）。撤销完成写软标记 `pending`，不删行，用户填过的原因要留着。
4. **算今天**：`TaskScheduleEngine.entriesFor(日期, 任务, 当天打卡, 日型, 计划状态表, 目标状态表)` 返回四个段（每日固定/每日留白/临时今天/杂项）+ 已过期 + 漏做 + 已完成，以及完成率的分母分子。规则全部在这个文件里：区间、`everyday/weekdays/custom/interval`、`workday_only/holiday_only`、临时任务"到那天才出现、过了就过期"、留白回填。
5. **日型从哪来**：`HolidayCalendar`（内置法定假日表，**目前为空**，见已知坑）+ `day_overrides` 表（用户手标班/休）→ `dayTypeOf()`。
6. **影响谁**：安排页（`ScheduleScreen`）、记录页统计、AI 评价/日记的任务口径（**尚未接入，仍读老列**）。

## 对外接口 / 被谁调用
- `entriesFor / missedOn / isScheduledOn / dayTypeOf / isEffectivelyDone / streakOf` → 安排页 `ScheduleViewModel` 与目标/计划详情页两个 ViewModel 调；日历页、评价、日记**目前仍未接入**。
- `progressOf(tasks, plans, goals, occurrences, from, to, dayTypeOfDate)` → 目标/计划详情页的进度条与"近 N 天"口径；它只做累计，某天该不该做仍问引擎。
- `TaskWriteBridge.{saveTask,check,uncheck,markNotDone,archive,pause,resume}` → 只被 `ScheduleViewModel` 与 `GoalDetailViewModel/PlanDetailViewModel` 调。老的 `RecordListViewModel.completeTask` 还在用老列自己写（见已知坑 3）。

## 依赖的上游
`DateFormats`（取"今天"）、Room、`FestivalProvider`/`LunarCalendar`（只做节日名展示，**不参与**工作日判定）。

## 关键数据结构
- `tasks.kind`：`daily` 每日固定 / `adhoc` 临时一次 / `blank` 每日留白。
- `tasks.repeatRule`：`everyday` / `weekdays` / `custom`+`weekdaysCsv`（ISO 周一=1…周日=7）/ `interval`+`intervalDays`（锚点=开始日，缺则创建日）。
- `tasks.dayPolicy`：`all` / `workday_only` / `holiday_only`。
- `tasks.scheduledDate` vs `dueDate`：前者"哪天开始出现在今天"，后者"最后期限，过了就过期"。
- `task_occurrences.status`：`done` / `not_done`（带 `reasonCode`+`reasonNote`）/ `pending`（撤销）。`note` 装留白回填内容，`actualMinutes` 装实际时长。
- `tasks.status`：`active` / `paused` / `archived`（老「真正完成」的等价物就是 `archived`）。
