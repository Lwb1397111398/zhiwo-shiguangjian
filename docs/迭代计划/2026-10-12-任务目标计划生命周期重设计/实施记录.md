## 范围确认（调查阶段结论）

删除任务后记录复活成杂项的完整链条（代码证据）：
1. `ScheduleViewModel.deleteTask`（:255-260）物理删任务行，不碰来源记录；
2. 记录 category 在建任务的两条路径（`convertRecordToTask` :279-289、AI 抽取 `InputViewModel` :114-118）中从未被改，恒为 "todo"；
3. 杂项谓词（`ScheduleViewModel` :103-106）`category=="todo" && tasks.none{recordId}` 重新成立 → 下一帧回杂项；
4. `MiscTodoRow`（`ScheduleScreen` :583-595）只有勾选/转任务两个出口，无删除、行也不可点 → 卡死。

同类死角排查共 14 处（B1-B14），修复清单见设计文档 §五。

## 待老板真机走查（本机无模拟器）

1. 删除由记录转来的任务 → 确认框是否提示"记录会回到杂项待办" → 在杂项行按删除 → 记录消失；
2. 勾完成一次性任务 → 当天在"今日已完成" → 次日起安排页不再出现（含已过期段）；
3. 暂停任务（编辑器）→ 总览页恢复 → 提醒重新生效；
4. 删除目标 → 其下计划/任务是否如提示转为自由并能在总览页看到。
