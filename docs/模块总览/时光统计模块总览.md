# 时光统计模块总览

## 模块职责

把「每天的时间计划与真实投入」算出来、画出来：今日时间环（时间花在哪）、近 14 天趋势（和前几天比如何）、本月热力图（一个月的节奏），以及打卡时顺手补记「实际花了多久」。不新增任何数据库表，不引第三方图表库。

## 运作流程

1. **取数**：`TimeLensViewModel` 订阅 Room 五路 Flow（tasks / task_occurrences 全量 / day_overrides / plans / goals，写法仿 `CalendarViewModel`），合并成一个快照 Flow。任何一路变化才重算一次——数据不动就不算，这是性能上的第一道闸。
2. **计算**（全部在 `data/tasks/TimeLensCalculator.kt`，纯函数、不读时钟不读库、可 JVM 单测）：
   - 「某天该做什么」照旧只问 `TaskScheduleEngine.entriesFor`——本模块绝不自己判排期；
   - `todayBudget`：把当天的条目按归属聚成环的段（有计划算计划、没计划有目标算目标、都没有算「未归属」；按时长降序），同时产出今天计划总分钟、已记录实际分钟（当天 done 打卡的 `actualMinutes` 之和）、未定时长任务条数；
   - `lensPlannedMinutes`：时长口径的唯一出处——留白任务没填按 60 分钟，其余任务填 0 表示「不限」（不进环、只计条数）；
   - `dailyInvestment`：逐日产出（计划分钟、实际分钟、应做件数、完成件数），趋势柱与热力图共用同一份序列。
3. **展示**：
   - **安排页顶部胶囊卡**（`ui/components/TimeLensCard.kt`）：迷你环 + 「今日计划 X · 已记录 Y」+ 较昨日 ▲▼，可折叠（折叠状态记住），展开带 14 天小柱图；点整卡进全屏页。
   - **全屏「时光」页**（`ui/screens/TimeLensScreen.kt`，路由 `time_lens`）：大环（点环节/图例高亮该归属的任务清单）→ 近 14 天双柱（浅=计划、深=实际，点击柱看当天明细）→ 月度热力格（颜色深浅=当天已记录分钟，浅黄=排了但没记；点格子跳 `calendar?date=某天`）。
   - 图表全在 `ui/components/TimeLensChart.kt`：`LensDonut` / `TrendBars` / `HeatGrid` / `DoneRing`，全部 Compose Canvas 自绘，段色取 `lensColor(i)` 固定调色板——同一份 slices 在卡片和全屏页颜色必然一致。
4. **实际分数的来源**（闭环的进水口）：安排页勾选完成时（留白任务除外）弹出「实际花了多久？」小面板（`ScheduleScreen.ActualMinutesSheet`：快捷 chips + 自定义 + 可跳过），经 `ScheduleViewModel.recordActualMinutes` → `TaskOccurrenceRepository.setCheck` 落库。跳过不扣任何东西，只是趋势图里那天少一根深柱。

## 入口文件清单

- `data/tasks/TimeLensCalculator.kt` —— 口径唯一出处（纯函数）
- `app/src/test/java/com/zhiwo/shiguangjian/data/tasks/TimeLensCalculatorTest.kt` —— 10 个口径单测
- `ui/viewmodel/TimeLensViewModel.kt` —— 取数与装配
- `ui/components/TimeLensChart.kt` —— 环 / 柱 / 热力格 / 完成小环
- `ui/components/TimeLensCard.kt` —— 安排页顶部胶囊卡
- `ui/screens/TimeLensScreen.kt` —— 全屏统计页
- `ui/screens/ScheduleScreen.kt` —— 卡片插入点、ActualMinutesSheet、头部完成小环
- `MainActivity.kt` —— `time_lens`、`calendar?date={date}` 两个路由

## 对外接口 / 被谁调用

- 安排页（ScheduleScreen）：嵌 TimeLensCard、勾选后触发 ActualMinutesSheet；
- 日历页（CalendarScreen）：接收 `calendar?date=` 的 initialDate；
- 输出组件 LensDonut/TrendBars/HeatGrid/DoneRing 为 public，其他页面想复用直接 import `ui.components`。

## 依赖的上游模块

- 任务与排期（TaskScheduleEngine / 数据层 Room）：条目判定与打卡真值全靠它；
- 主题色板（ui/theme/Color.kt）：调色板由 Success/Warning/Lavender/Primary 等派生。

## 关键数据结构

- `TodayBudget(date, slices, plannedMinutes, unboundedCount, loggedMinutes)`；`LensSlice(key, title, minutes, items)`
- `DayInvestment(date, plannedMinutes, loggedMinutes, dueCount, doneCount)`
- 段 key 规则：`plan-{id}` / `goal-{id}` / `free`（未归属）

## 性能约束（老板点名要求）

- 图表零依赖、Canvas 自绘：无第三方库初始化，柱/格数量恒定（≤42 格、14 柱），无列表抖动；
- ViewModel 层 combine Flow 只在数据变化时重算；趋势只算 14 天、热力只算当月（`dailyInvestment` 每天调一次引擎，纯函数无 IO，实测毫秒级——UNMEURED：未在真机 profile）；
- 动画只用 `Animatable`/`animateIntAsState` 的一次性补间与弹簧，**没有任何无限循环动画**（呼吸感靠数据变化触发，不靠常驻帧）。

## 已知坑与约束

- **2026-09-21 之前与功能上线前的普通打卡没有实际分钟**（历史回填全 0）：趋势图中深柱缺失是如实反映，不是 bug；
- v13 双写期：`TaskWriteBridge.check` 加了 `minutes` 参数，`setCheck` 的合并语义保证补录不覆盖原因与备注；
- 日历圆点口径已改成**只数当日 adhoc 临时任务**（`CalendarViewModel.specialCount`）——每日固定/留白天天都有，打点反而失真；点日期仍显示全部任务；将来想加「漏做红点」在此函数旁加一行即可；
- 目标/计划颜色的语义（用户自定义色）暂未接：环的段色是按份额排序的调色板色，不是归属本身的颜色；
- 深色模式：调色板直接用主题色常量，深浅色下对比度未逐一走查（待真机确认）。
