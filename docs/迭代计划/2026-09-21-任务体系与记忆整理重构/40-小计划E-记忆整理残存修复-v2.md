## E.1 七成因与处置（结论同 v1，此处只列 v2 强化项）

| # | 根因（证据） | v2 处置 |

## E.2 v2 新增硬要求

1. **新 op 双处登记**（漏一处即静默失效）：`OpPayloads.kt` 的 `OpType.executionOrder`（:14-16）与 `OpValidator.decide`（:55-61，未知类型直接 Invalid）。门禁：`grep -n "MERGE_MEMORY\|SPLIT_MEMORY\|DELETE_MEMORY" app/src/main/java/com/zhiwo/shiguangjian/data/organizeops/*.kt` 三个文件（实体枚举/validator/executor）都要命中。
2. **DELETE 提案预览必须显示受影响任务数**：「将删除 N 条记录，影响 M 条活跃任务」（M 来自 `tasks WHERE recordId IN (:ids)`）。这是 C2/A1 之后新出现的连带面 —— v13 里 `recordId` 暂时还是 CASCADE，**M>0 时必须禁用一键执行并提示先处理任务**，v14 改成 SET NULL 后放宽为纯提示。
3. **`under_review` 保护**：整理不得把 `under_review` 记忆直接改成 `superseded`（现在可以，OpValidator.kt:130 只特判 superseded）→ 执行前判定 STALE，交回用户在对账队列决策。
4. **prompt 注入面回归**：`getActiveMemories`（MemoryDao.kt:12）现在无人调用 → 本次把它接到 AiRepository/评价/日记的实际注入点，并加断言：`superseded`/`under_review` 不得进入任何 prompt。
5. `MemorySimilarity` 独立 `object`，**不得**放在 `ReviewViewModel.Companion`（外层是 AndroidViewModel，JVM 加载即危）。

## E.4 用例（挂编号）

`MemorySimilarityTest` `MF-S01..S14`：空/全空格；全角标点→半角；大小写；`CONTAINS` 长度阈值边界；bigram 0.71 vs 0.73；中英混排；纯英文小写归一；「我喜欢跑步」vs「我喜爱跑步」=SIMILAR；「我在准备法考」vs「我今年通过法考」=DIFFERENT（防过度合并）；自反性必 EXACT；含引号/换行；只有标点差异=EXACT；一条是另一条前缀=CONTAINS；normalize 幂等。
`DependencyCascadeTest` `MF-C10..C15`：单层链；三层链；有环不死循环；多父依赖需全部父被取消才级联；无依赖只改自己；撤销恢复集合正确。
`OpValidatorTest` 扩 `MF-V01..V06`：EXACT/CONTAINS 判重不放行；MERGE 传 1 个 id 非法；SPLIT parts<2 非法；under_review 目标 → STALE；内容 hash 变化 → STALE；未知类型 → Invalid。
`OrganizeOpExecutorTest`（纯逻辑部分）`MF-X01..X04`：MERGE 产新行 + 旧行 superseded 且 supersededBy 指向新行；SPLIT 产 N 行；DELETE_MEMORY 是唯一物理删路径；occurredAt 与 createdAt 分工。
R6 前置的解析测试 `MF-P01..P04`：`{text,sourceIds}` 正常解析；缺 sourceIds → 该条建议被丢弃并计数（不得退化成"删全部"）；sourceIds 含不存在的 id → 过滤；重复 id 去重。
不可 JVM 证：两轮连续整理不产生第 3 条同义记忆、旧批次在真机 v12 存量下的可见性 → 标【真机-老板】。
