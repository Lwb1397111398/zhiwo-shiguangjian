### C2.2 手动新建/编辑（"自定义性弱"的直接解药；现在全 App 无此入口）
字段与显隐规则同 v1（kind 三选 + 起止 + 重复 + 节假日策略 + 指定哪天出现 + 期限 + 时长 + 提醒时间 + 所属计划/目标 + 颜色 + 暂停/结束/删除）。v2 补：
- **「结束任务」= `status='archived'`**，是旧 `isPermanentlyCompleted`（"每日任务真正完成后不再刷新"，TaskItem.kt:104、CalendarViewModel.kt:74-81）的新模型出口 —— 语义迁移必须在总览里写一句，否则老用户找不到"真正完成"按钮。
- 删除确认显示真实连带数字：「连带删除 N 条打卡记录」（来自 `countByTask`），不用"若干"。
- 层级自动纠正：选了 plan 就按 `plan.goalId` 覆盖 `task.goalId`（`TaskEditValidation.alignHierarchy`）。
- 校验（全部纯函数、全部有单测）：内容为空；`endDate < startDate`；custom 未勾星期；`dueDate < scheduledDate` → 提示但允许；`remindTime` 非法（含 `24:00`）；`durationMinutes` 越界（0-1440）；归属日期超出 `[today-7, today]`。
- 保存后调 `ScheduleSyncService.onTaskSaved(task)`（F 实现闹钟/日历；C2 先建空实现 + 接口，避免 F 阶段大改 UI）。

### C2.3 打卡交互
| 操作 | 行为 | 落库（唯一入口 `setCheck`） |
|---|---|---|
| 点圆圈 | 完成 | `setCheck(taskId, date=今天, status=done)` |
| 「没做完」/长按 | 6 预设原因 + 自由文本 + 实际时长 + **归属日期** | `setCheck(status=not_done, reasonCode, reasonNote)` |
| 留白「回填这 1 小时」 | 多行文本 + 实际时长 + 归属日期 / 「跳过今天」 | `setCheck(note=…)` / `setCheck(not_done, skipped_blank)` |
| 再点已完成 | 撤销 | `occurrenceRepository.undo(taskId,date)`（删行） |
| 过期行 | 改到今天 / 补打卡（选归属日期）/ 放弃（archived） | `updateTask` / `setCheck` / `updateTask` |
| 待补录行 | 补打卡 / 补原因 | `setCheck(date=漏做那天)` |
- 淡出动画判据改为「引擎结果 == DONE_TODAY」，用 `LazyColumn` 的 `animateItem`，删除现在 `fadingTaskIds/completingRecordIds` 两套本地状态（RecordListScreen.kt:80-81、162-174）。
