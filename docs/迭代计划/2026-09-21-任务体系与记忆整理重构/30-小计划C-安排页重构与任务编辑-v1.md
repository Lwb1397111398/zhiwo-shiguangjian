## C.2 安排页结构（自上而下）

```
标题行：今日安排 / 日期 + 农历·节日    完成率环 3/5      [⋯ 显示设置]   [+ 新建]
① 每日 · 固定            段头含 "3/5"，点击折叠
② 每日 · 留白 (60 分钟)   主按钮「回填这 1 小时」
③ 临时 · 今天
④ 已过期 (n)             每条：改到今天 / 补打卡 / 放弃
⑤ 进行中的计划 (n)        卡片：起止、剩余天数、进度条、任务数 → 点进详情
⑥ 目标 (n)               卡片：截止、计划数、总进度 → 点进详情
⑦ 今日已完成 (n) 折叠     含留白回填内容回显
⑧ 待回填 (n) 折叠         仅 blank 跨天未填时出现
```
- 段①-③④⑦⑧ 的数据全部来自 `buildDayPlan(today, ...)` 一次调用，页面不再各自 filter。
- 「+ 新建」菜单三项：新建任务 / 新建计划 / 新建目标。
- 空段：只显示段头 + 一行浅色提示（「今天没有固定任务」），**不显示空卡片占位**，减少噪音。
- 全部段落按「显示设置」的顺序与显隐渲染，默认顺序即上图。

## C.3 任务行（TaskRow）交互契约

| 操作 | 行为 | 落库 |
|---|---|---|
| 点圆圈 | 完成打卡（daily/blank/adhoc 通用） | `upsert(occurrence, done)`，行淡出动画后移到段⑦ |
| 长按行 / 点「没做完」 | 弹未完成原因：预设 6 项（没时间/太累/生病/忘了/情况变了/其他）+ 自由文本 + 可选实际时长 | `upsert(not_done, reasonCode, reasonNote)` |
| 点行文本 | 进 `task_edit`（编辑） | — |
| 留白行点「回填」 | 弹输入框（多行）+ 实际时长 + 「跳过今天」 | `upsert(note=...)` / `upsert(not_done, skipped_blank)` |
| 过期行「改到今天」 | `scheduledDate = today`（保留 dueDate） | `updateTask` |
| 过期行「放弃」 | `status = archived` | `updateTask`，并进归档列表 |
| 已完成的行再点 | 撤销打卡 | **删除** occurrence（B.3.21），淡入回原段 |

动画保留现有淡出风格（RecordListScreen.kt:162-174），但淡出判据改为「引擎返回 DONE_TODAY」，不再是 `taskType=="daily"` 硬编码。

## C.4 任务编辑器（TaskEditScreen）——「自定义」的落点

字段（按 kind 动态显隐）：
- 公共：`内容`（必填，trim 后非空才允许保存）、`所属计划`（下拉：进行中计划 + 「无」）、`所属目标`（选了计划则自动带出该计划的 goal，可覆盖）、`颜色`（6 色）、`时长`（分钟，快捷 15/30/45/60/90）、`提醒时间`（`HH:mm` 时间选择器，清空=不提醒）
- `kind` 单选：每日固定 / 临时一次 / 每日留白（图标 + 一句话解释，例：「每日固定：每天/每周重复，如读书 1 小时」「临时：某天做一件事，如交材料」「留白：每天留一段空白，事后回填做了什么」）
- kind=daily 专属：`重复`（每天 / 工作日 / 自定义星期多选 / 每隔 N 天）、`开始日期`、`结束日期`（含「长期」开关）、`节假日策略`（照常 / 只在工作日 / 只在休息日）
- kind=adhoc 专属：`哪一天出现`（默认今天，可指定未来日 → 兑现"9 月 22 日才显示"）、`最后期限`（可空）
- kind=blank 专属：`时长`（默认 60）、`节假日策略`
- 底部动作：保存 / 暂停（`status=paused`）/ 归档（`status=archived`）/ 删除（二次确认，提示会连带删除该任务的打卡史 N 条 —— 数字来自 `task_occurrences` 计数，不写虚数）
- 校验：`endDate < startDate` → 红色提示并禁止保存；`weekdays` 选 custom 但一个都没勾 → 禁止保存；`dueDate < scheduledDate` → 允许但提示「期限早于出现日期，这天一到就会显示过期」。
- 保存后副作用（F 完善闹钟/日历，C 先接线）：调 `ScheduleSyncService.onTaskSaved(task)`（闹钟重排 + 日历事件同步），失败只 Toast 不阻塞保存。

新建计划/目标用同一个 `PlanEditScreen`（传 `mode=goal|plan`）：目标只有 `targetDate` 没有 `endDate` 字段差异之外的东西，复用减少一份 UI。

## C.5 ViewModel 契约（`ScheduleViewModel`）

```kotlin
val today: StateFlow<String>                      // DateFormats.nowDate() 唯一调用点
val dayPlan: StateFlow<DayPlanResult>             // combine(tasks, occurrences(today), overrides) 
val plans: StateFlow<List<PlanEntity>>; val goals: StateFlow<List<GoalEntity>>
val display: StateFlow<ScheduleDisplayPrefs>      // 段显隐+顺序
fun complete(taskId); fun markNotDone(taskId, reason, note, minutes); fun undo(taskId)
fun fillBlank(taskId, note, minutes); fun skipBlankToday(taskId)
fun moveOverdueToToday(taskId); fun archive(taskId)
fun setSectionVisible(id, Boolean); fun moveSection(id, delta)
```
- 组合方式：`combine(taskDao.getAllWithStatusActive(), occurrenceDao.getOccurrencesForDateFlow(today), dayOverrideDao.getAllFlow())` → 纯函数 `buildDayPlan`。
- **不在 ViewModel 里写任何排期规则**（否则 B 的单一入口就白设计了）；VM 只做数据装配与调用引擎。
- 手动构造 Repository（沿用现有无 DI 风格，总体方案 §12）。
