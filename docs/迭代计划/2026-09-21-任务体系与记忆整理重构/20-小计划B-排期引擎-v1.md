## B.2 公开 API

```kotlin
enum class DayType { WORKDAY, HOLIDAY }
enum class TaskKind { DAILY, ADHOC, BLANK }          // 对应列值 daily / adhoc / blank
enum class EntrySection { DAILY_FIXED, DAILY_BLANK, ADHOC_TODAY, OVERDUE, DONE_TODAY, UNFILLED }
enum class EntryState { DUE, DONE, NOT_DONE, OVERDUE, UPCOMING, UNFILLED }

data class DayEntry(
    val task: TaskEntity,
    val occurrence: TaskOccurrenceEntity?,
    val state: EntryState,
    val section: EntrySection,
    val sourceLabel: String?      // 来自哪个计划/目标，用于行内 "#法考冲刺" 标记
)
data class DayPlanResult(
    val entries: List<DayEntry>,
    val dueCount: Int,            // 应做数（完成率分母；不含 UPCOMING/UNFILLED）
    val doneCount: Int,
    val sections: Map<EntrySection, List<DayEntry>>
)

fun dayTypeOf(date: String, overrides: List<DayOverrideEntity>): DayType
fun isScheduledOn(task: TaskEntity, date: String, dayType: DayType): Boolean
fun buildDayPlan(date, tasks, occurrences, overrides, sourceNames): DayPlanResult
fun isEffectivelyDone(task, occurrence, date): Boolean         // 唯一完成态判据
fun streakOf(taskId, occurrences, today): Int                   // 连续打卡天数
fun progressOf(tasks, occurrences, from, to): Progress         // 计划/目标进度
```
- 引擎是 `object`/顶层纯函数，输入全部显式传入（date、tasks、occurrences、overrides），**不读库、不读时钟**；`DateFormats.nowDate()` 只在调用方（ViewModel）出现一次。这是能在 JVM 里测干净的前提。

## B.3 判定规则（逐条可测）

### B.3.1 通用前置（任何 kind）
1. `task.status != "active"` → 不进入日计划（paused/archived 只在「已暂停/已结束」列表出现）。
2. `startDate` 非空且 `date < startDate` → 不出现（adhoc 例外见 B.3.3，产出 UPCOMING）。
3. `endDate` 非空且 `date > endDate` → 不出现。
4. 日期比较一律用 `yyyy-MM-dd` 字符串字典序（等长零填充，字典序=时间序），**不做时区换算**：与现有 `DateFormats.nowDate()`（设备本地时区）一致，跨时区旅行时以设备日期为准 —— 明确写为该 App 的既定语义，避免"UTC 存本地看"的漂移。

### B.3.2 kind = daily（每日固定）
5. 重复规则：`everyday` 命中每天；`weekdays` 命中周一~周五（不看节假日，与 dayPolicy 独立）；`custom` 命中 `weekdaysCsv` 包含 ISO 星期（周一=1…周日=7，`weekdaysCsv` 为空时按 `everyday` 处理并记一次日志）；`interval` 从 `startDate`（空则 `createdAt` 的日期）为**第 0 天锚点**，`(date - anchor).days % intervalDays == 0` 命中。
6. 节假日策略 `dayPolicy`：`all` 不额外过滤；`workday_only` 只在 `dayType == WORKDAY` 出现；`holiday_only` 只在 `HOLIDAY` 出现。
   → `weekdays` + `workday_only` 是两种不同表达（前者看星期，后者看调休后的实际上班日），互不冲突但可叠加，叠加时取交集。
7. 有 occurrence 且 `status=done` → 段 `DONE_TODAY`、state DONE；有 occurrence 且 `status=not_done` → 留在 `DAILY_FIXED`、state NOT_DONE（行内显示"未完成·<原因>"，可改判）。
8. 当天已过（`date < today`）且该日无 occurrence → **不进入今天的列表**，只在打卡史/漏做统计里出现。daily 任务不用"已过期"这个刺眼标签（漏做≠失败），统计口径叫「漏做 N 天」。

### B.3.3 kind = adhoc（临时一次性）
9. `scheduledDate` 非空且 `date == scheduledDate` → 出现在 `ADHOC_TODAY`（"只有那天才显示"的原始诉求）。
10. `scheduledDate` 非空且 `date < scheduledDate` → UPCOMING（默认不占今日列表，可在"即将开始"折叠视图看）。
11. `scheduledDate` 非空且 `date > scheduledDate` 且无 done occurrence → `OVERDUE` 段，state OVERDUE（"没做完就会显示过期"）。
12. `scheduledDate` 为空 → 从创建日起持续出现在 `ADHOC_TODAY`，直到完成或超过 `dueDate` → OVERDUE。
13. `dueDate` 非空时优先级高于 9-12：`date > dueDate` 且未完成 → OVERDUE（即使 scheduledDate 是今天之后，脏数据 `dueDate < scheduledDate` 直接判 OVERDUE，不丢任务）。
14. done occurrence 存在（任意日期）→ `DONE_TODAY`，并在行内显示实际完成日期（补打卡场景）。

### B.3.4 kind = blank（每日留白）
15. 每天命中一次（受 `startDate/endDate/dayPolicy` 约束），默认 `durationMinutes=60`。
16. 无 occurrence → `DAILY_BLANK` 段、state DUE，行内主按钮是「回填这小时做了什么」。
17. 有 occurrence 且 `note` 非空 → `DONE_TODAY`（内容回显）。有 occurrence 但 `note` 空且 `status=done` → 视为已填（用户可能只勾选），state DONE。
18. 今天之前、完全没有 occurrence → `UNFILLED`（待回填），**不计入完成率分母、不算漏做**。用户可"补填"或"跳过"（跳过写一条 `status=not_done, reasonCode=skipped_blank` 让它消失）。

### B.3.5 打卡与撤销（occurrence 写入语义）
19. 打卡 = `upsert(taskId, date, status=done, actualMinutes?=durationMinutes)`，REPLACE 幂等。
20. 「没做完」= `upsert(status=not_done, reasonCode, reasonNote)`；再点完成 → 覆盖为 done，保留 `reasonNote` 于 note 字段（原因不丢，符合"我后来补做了"的实情）。
21. 撤销完成（`uncomplete`）→ **删除**该 occurrence（而不是写 pending 行），保持"表里只有真实发生过的事"。撤销后该任务回到 DUE。
22. `actualMinutes` 允许用户改（跑 40 分钟但计划 60 分钟），不改 `durationMinutes`（那是计划）。

### B.3.6 24:00 与"今天"的边界
23. 「今天之前」的定义是**日历日**比较（字符串），不用时间戳；23:59 打卡算今天，00:01 打卡算明天。
24. 跨零点不需要"重置动作"：完成态来自 occurrence 是否存在（A 里已删 `resetDailyTasksForNewDay` 与 ZhiwoApplication.kt:59-61 的调用）。这是修"重启才刷新/不刷新"这类怪现象的根本修法，必须在计划里显式记录，防止有人把它加回来。

## B.4 节假日数据（`HolidayCalendar`）

现状：`FestivalProvider.kt:10-77` 只有节日**名字**，没有任何"是否放假/补班"语义；`SpecialDateEntity` 是用户纪念日。所以工作日判定必须新建，且**不许凭记忆编**。

三层判定，优先级从高到低：
1. **用户覆盖表** `day_overrides(date PRIMARY KEY, type 'workday'|'holiday', createdAt)` —— 用户在日历页长按某天即可改，最可信。
2. **内置法定安排表**：`HolidayCalendar` 内置常量表，按年份分节，包含「放假日」与「调休上班日」两类。
   数据来源硬要求：实现时用网络检索取**国务院办公厅关于当年部分节假日安排的通知**原文核对后写死，并在文件头注明来源与录入日期；**查不到的年份不填**，绝不凭推测补数据（这是老板明确讨厌的"糊过去"）。当前计划只录 2026 年（已过半年，公告确定），2027 年公告未出则留空并在设置页标注"该年按周末判定"。
3. **兜底规则**：`weekend → HOLIDAY，Mon-Fri → WORKDAY`。

```kotlin
object HolidayCalendar {
    fun holidayOf(date: LocalDate): Boolean?      // null = 该年无内置数据
    fun makeupWorkdayOf(date: LocalDate): Boolean?// 调休上班日
    fun dayTypeOf(date: LocalDate): DayType       // 内置 + 兜底，不含用户覆盖
}
fun dayTypeOf(date: String, overrides: List<DayOverrideEntity>): DayType  // 引擎入口，含覆盖
```
`isLunar` 农历节日已可由 `LunarCalendar` 换算，内置表按公历日期存（每年公告给出的就是公历日期），不需要农历。

## B.5 进度与统计（D 要用，B 就实现，避免 D 再造一份）

```kotlin
data class Progress(val due: Int, val done: Int, val percent: Int, val streak: Int, val missedDates: List<String>)
fun progressOf(tasks: List<TaskEntity>, occurrences: List<TaskOccurrenceEntity>, from: String, to: String, overrides: ...): Map<String, Progress>
```
- 分母 = 区间内 `isScheduledOn` 为 true 的 (task, date) 组合数（daily/blank 逐日展开；adhoc 按 scheduledDate 计一次）。
- 目标/计划进度 = 其下所有任务（含子计划任务）的合并 Progress；空集合时 `percent=0` 且 `due=0` → UI 显示"暂无排期"，不显示 0%（避免"我做了事却显示 0%"的误导）。
- 展开区间上限：`to - from` 超过 366 天时截断到 366 天并记日志（防误用导致卡顿）。
